# Enable Fault Tolerance and Failure Detection (啟用容錯和故障檢測)
## Handle temporary failures (處理臨時故障)
通常，分佈式系統使用基於仲裁的方法來處理故障。仲裁是分佈式事務繼續執行操作所需的最少票數。如果伺服器是共識的一部分並且已關閉，那麼我們無法執行所需的操作。它會影響我們系統的可用性和持久性。

我們將使用草率仲裁而不是嚴格的仲裁成員資格。通常，領導者管理共識參與者之間的通信。參與者在提交成功寫入後發送確認。收到這些確認後，領導者將響應客戶端。但是，缺點是參與者容易受到網絡中斷的影響。如果領導者暫時關閉並且參與者無法聯繫到它，他們會宣布領導者死亡。現在，必須重新選舉新的領導者。這種頻繁的選舉會對性能產生負面影響，因為系統在挑選領導者上花費的時間比完成任何實際工作都要多。

在草率仲裁中，首選列表中的前 n 個健康節點處理所有讀寫操作。當在一致性哈希環中順時針移動時，n 個健康節點可能並不總是發現的前 n 個節點。

讓我們考慮以下 n = 3 的配置。如果節點 A 在寫入操作期間暫時不可用或無法訪問，則將請求發送到首選列表中的下一個健康節點，在本例中為節點 D。它確保了所需的可用性和耐久性。處理請求後，節點 D 包含有關哪個節點是預期接收者 (在本例中為 A) 的提示。一旦節點 A 再次啟動並運行，節點 D 就會向 A 發送請求資訊，以便它可以更新其資料。傳輸完成後，D 將從其本地存儲中刪除該項目，而不影響系統中的副本總數。

[處理臨時故障](./failures)

這種方法稱為提示切換。使用它，如果節點面臨臨時故障，我們可以確保讀取和寫入得到滿足。

## Handle permanent failures (處理永久性故障)
如果節點發生永久性故障，我們應該保持副本同步，以使我們的系統更加耐用。我們需要加快副本之間不一致的檢測，並減少傳輸資料的數量。我們將為此使用 Merkle 樹。

在 Merkle 樹中，單個鍵的值被哈希並用作樹的葉子。在樹的較高位置的父節點中有其子節點的哈希值。Merkle 樹的每個分支都可以獨立驗證，而無需下載完整的樹或整個資料集。在檢查副本之間的不一致時，Merkle 樹減少了必須交換的資料量。例如，如果兩個樹根的哈希值相同且其葉節點也相同，則無需同步。直到該過程到達樹葉，當節點交換子節點的哈希值時，主機才能識別不同步的鍵。Merkle 樹是一種實現反熵的機制，這意味著保持所有資料一致。它減少了用於同步的資料傳輸和反熵過程中訪問的光盤數量。

### Anti-entropy with Merkle trees (使用 Merkle 樹進行反熵)
每個節點為它為每個虛擬節點託管的鍵範圍保留不同的 Merkle 樹。節點可以確定給定範圍內的鍵是否正確。對應於公共鍵範圍的 Merkle 樹的根在兩個節點之間交換。我們將進行以下比較：

- 比較 Merkle 樹根節點的哈希值。
- 如果它們相同，請勿繼續。
- 使用遞歸遍歷左右子節點。節點識別它們是否有任何差異並執行必要的同步。

使用 Merkle 樹的優點是可以獨立檢查 Merkle 樹的每個分支，而無需節點下載樹或完整資料集。它減少了同步必須交換的資料量以及反熵過程中所​​需的光盤訪問次數。

我們希望我們的節點檢測環中其他節點的故障，所以讓我們看看如何將其添加到我們的擬議設計中。

## Promote membership in the ring to detect failures (在環中促進成員資格以檢測故障)
節點可以離線很短的時間，但也可能無限期地離線。當單個節點關閉時，我們不應該重新平衡分區分配或修復無法訪問的副本，因為這很少是永久離開。因此，應小心地從環中添加和刪除節點。

節點的計劃調試和退役導致成員資格變更。這些變更形成歷史。它們將持久記錄在每個節點的存儲中，並使用八卦協議在環成員之間進行協調。基於八卦的協議還維護成員資格的最終一致視圖。當兩個節點隨機選擇彼此作為對等節點時，兩個節點都可以有效地同步其持久的成員歷史記錄。

讓我們通過考慮以下示例來了解基於八卦的協議是如何工作的。假設節點 A 第一次啟動，它隨機將節點 B 和 E 添加到其令牌集中。令牌集在一致哈希空間中具有虛擬節點，並將節點映射到各自的令牌集。此資訊存儲在節點的磁盤空間本地。

現在，節點 A 處理導致更改的請求，因此它將其傳達給 B 和 E。另一個節點 D 在其令牌集中具有 C 和 E。它進行更改並告訴 C 和 E。其他節點執行相同的過程。這樣，每個節點最終都知道每個其他節點的資訊。這是一種異步共享資訊的有效方式，並且不會佔用大量帶寬。

Question
記住我們的一致性哈希方法，基於八卦的協議會失敗嗎？

Answer
是的，基於八卦的協議可能會失敗。例如，節點 A 的虛擬節點 N1 想要添加到環中。管理員詢問 N2，它也是 A 的虛擬節點。在這種情況下，兩個節點都認為自己是環的一部分，並且不會意識到它們是同一個伺服器。如果進行任何更改，它將繼續自我更新，這是錯誤的。這稱為邏輯分區。
```

```
Question 2
我們如何防止邏輯分區？

Answer
我們可以讓幾個節點扮演種子的角色，以避免邏輯分區。我們可以通過配置服務將一組節點定義為種子。所有工作節點都知道這組節點，因為它們最終可以與種子協調成員資格。所以，邏輯分區是非常罕見的。
```

去中心化故障檢測協議使用基於八卦的協議，允許每個節點了解其他節點的添加或刪除。顯式節點的加入和離開方法通知節點有關永久節點添加和刪除的資訊。當單個節點無法與另一個節點通信時，它們會檢測到臨時節點故障。如果節點在授權時間內無法與其令牌集中存在的任何節點通信，則它會與管理員通信，告知該節點已死亡。

## Conclusion (結論)
鍵值存儲提供了靈活性，並允許我們擴展具有非結構化資料的應用程式。Web 應用程式可以使用鍵值存儲來存儲有關使用者會話和偏好的資訊。使用使用者鍵時，所有資料均可訪問，鍵值存儲非常適合快速讀寫操作。鍵值存儲可用於支持實時推薦和廣告，因為存儲可以快速訪問並呈現新鮮推薦。
