# Global and Local Load Balancing (全局和本地負載平衡)
## Introduction (簡介)

從上一課看來，似乎負載平衡僅在資料中心內執行。但是，全球和本地規模都需要負載平衡。讓我們了解兩者的功能：

```
全球伺服器負載平衡 (GSLB)：GSLB 涉及跨多個地理區域的流量負載分佈。

本地負載平衡：這是指在資料中心內實現的負載平衡。這種類型的負載平衡側重於提高效率和更好地利用資料中心託管伺服器的資源。
```


讓我們了解下面的兩種技術。

## Global server load balancing (全球伺服器負載平衡)
GSLB 確保將全球到達的流量負載智能地轉發到資料中心。例如，資料中心電源或網絡故障要求將所有流量重新路由到另一個資料中心。GSLB 根據使用者的地理位置、不同位置的託管伺服器數量、資料中心的健康狀況等做出轉發決策。

在下一課中，我們還將學習 GSLB 如何提供自動區域故障轉移。GSLB 服務可以安裝在本地，也可以通過負載平衡即服務 (LBaaS) 獲得。

下圖顯示 GSLB 可以將請求轉發到三個不同的資料中心。資料中心內的每個本地負載平衡層都將與 GSLB 保持控制平面連接，提供有關 LB 和伺服器場健康狀況的資訊。GSLB 使用此資訊來驅動流量決策，並根據每個區域的配置和監控資訊轉發流量負載。

### Load balancing in DNS (DNS 中的負載平衡)
我們了解 DNS 可以針對 DNS 查詢響應多個 IP 地址。在關於 DNS 的課程中，我們討論了在查看 nslookup 的輸出時可以通過 DNS 進行負載平衡。DNS 使用一種簡單的技術，即重新排序 IP 地址列表以響應每個 DNS 查詢。因此，不同的使用者會得到重新排序的 IP 地址列表。這導致使用者訪問不同的伺服器來處理他們的請求。通過這種方式，DNS 將請求負載分佈在不同的資料中心。這是執行 GSLB。特別是，DNS 使用循環法來執行負載平衡，如下所示：

[DNS 中的負載平衡](./lb)


如上所示，DNS 中的循環法以嚴格的循環順序將客戶端轉發到資料中心。但是，循環法有以下限制：

```
不同的 ISP 擁有不同數量的使用者。服務於許多客戶的 ISP 將向其客戶端提供相同的緩存 IP，從而導致終端伺服器上的負載分佈不均。

因為循環負載平衡算法不考慮任何終端伺服器崩潰，所以它會繼續分發崩潰伺服器的 IP 地址，直到緩存條目的 TTL 到期。在這種情況下，服務的可用性可能會因為 DNS 級別的負載平衡而受到影響。

儘管存在局限性，但循環法仍被許多 DNS 服務提供商廣泛使用。此外，DNS 對緩存條目使用短 TTL 以在不同資料中心之間進行有效的負載平衡。
```

```
注意：DNS 不是 GSLB 的唯一形式。應用程式交付控制器 (ADC) 和基於雲的負載平衡 (稍後討論) 是執行 GSLB 的更好方法。
```

```
應用程式交付控制器 (ADC) 是應用程式交付網絡 (ADN) 的一部分。它們可以被視為提供各種服務 (包括負載平衡) 的 LB 的超集。ADC 的主要任務是執行 Web 加速以減少伺服器場的負載。第 3 層和第 7 層之間的一些著名服務包括緩存、SSL 卸載、代理/反向代理服務、IP 流量優化等等。ADC 也實現 GSLB。
```

### The need for local load balancers (對本地負載平衡器的需求)
DNS 在平衡負載方面起著至關重要的作用，但它有以下局限性：

```
DNS 數據包的大小很小 (512 字節)，不足以包含伺服器的所有可能 IP 地址。

對客戶端行為的控制有限。客戶端可以從接收到的 IP 地址集中任意選擇。一些接收到的 IP 地址可能屬於繁忙的資料中心。

客戶端無法確定要建立連接的最近地址。雖然可以實現 DNS 地理定位和類似任播的解決方案，但它們並不是簡單的解決方案。

在發生故障的情況下，由於緩存機制，通過 DNS 恢復可能會很慢，特別是當 TTL 值較長時。
```

為了解決上述一些問題，我們需要另一層負載平衡，即本地 LB。在下一課中，我們將討論有關本地負載平衡器的詳細資訊。


## What is local load balancing? (什麼是本地負載平衡？)
本地負載平衡器位於資料中心內。它們的行為類似於反向代理，並儘最大努力在可用伺服器池中分配傳入請求。傳入的客戶端請求無縫連接到使用虛擬 IP 地址 (VIP) 的 LB。

```
反向代理是伺服器端網絡邊緣的組件，位於伺服器和外部世界之間。它可以提供隱私、安全、緩存等功能。
```

```
VIP 是一個沒有物理機器與之對應的地址。實際上，許多機器將使用相同的虛擬 IP 地址。網絡上接口的故障會導致發送給它的數據包丟失。但是，使用 VIP，數據包會自動重新路由到故障轉移機器。從外部看，VIP 將顯示為一台機器。然而，在內部，一組機器將使用相同的地址。



DNS 查詢通常用 VIP 響應。
```

```
Question
DNS 可以被認為是全球伺服器負載平衡器 (GSLB) 嗎？

Answer
是的，實際上這有兩種進行全球流量管理 (GTM) 的方法：

通過 ADC 進行 GTM：一些 ADC 實現 GSLB。在這種情況下，ADC 具有託管伺服器的實時視圖，並根據資料中心的健康狀況和容量轉發請求。

通過 DNS 進行 GTM：DNS 通過分析客戶端的 IP 位置來進行 GSLB。對於每個請求域名 IP 的使用者 (例如 www.educative.io)，基於 DNS 的 GSLB 轉發地理位置更接近請求 IP 位置的資料中心的 IP 地址。
```
