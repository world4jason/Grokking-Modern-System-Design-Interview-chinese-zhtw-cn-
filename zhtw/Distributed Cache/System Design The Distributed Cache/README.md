# System Design: The Distributed Cache (系統設計：分佈式快取)
## Problem statement (問題陳述)
一個典型的系統由以下組件組成：

- 它有一個請求服務的客戶端。
- 它有一個或多個服務主機來接待客戶端請求。
- 它有一個服務用於資料存儲的資料庫。

在正常情況下，這種抽象表現良好。但是，隨著使用者數量的增加，資料庫查詢也會增加。結果，服務提供者負擔過重，導致性能緩慢。

在這種情況下，系統中會添加一個快取來處理性能惡化。快取是一個臨時資料存儲，通過將資料條目保存在記憶體中，可以更快地提供資料。快取僅存儲最頻繁訪問的資料。當請求到達服務主機時，它從快取中檢索資料 (快取命中) 並為使用者提供服務。但是，如果資料在快取中不可用 (快取未命中)，則將從資料庫中查詢資料。此外，快取中會填充新值，以避免下次快取未命中。

```
快取命中：當在快取中找到請求的資料時，伺服器立即響應資料。

快取未命中：當在快取中未找到請求的資料時，稱為快取未命中。
```

快取是一個非持久性存儲區域，用於保存重複讀取和寫入的資料，為最終使用者提供更低的延遲。因此，快取必須通過快速、具有足夠存儲空間且在我們擴展快取服務時美元成本可負擔的存儲組件提供資料。下圖突出顯示了 RAM 作為快取原始構建塊的適用性：

我們了解了對快取和合適存儲硬體的需求，但什麼是分佈式快取？讓我們接下來討論這個問題。

## What is a distributed cache? (什麼是分佈式快取？)
分佈式快取是一個快取系統，其中多個快取伺服器協調存儲頻繁訪問的資料。在單個快取伺服器不足以存儲所有資料的環境中，需要分佈式快取。同時，它是可擴展的，並保證了更高程度的可用性。

快取通常是小型、頻繁訪問及具有快速讀取時間的短期存儲。快取使用引用局部性原理。

```
引用局部性是指程序將在短時間內訪問一組特定資料的概念。局部性可以是空間的或時間的。
```

一般來說，分佈式快取在以下方面是有益的：

- 它們通過預先計算結果和存儲頻繁訪問的資料來最大限度地減少使用者感知的延遲。
- 他們從資料庫中預先生成昂貴的查詢。
- 他們臨時存儲使用者會話資料。
- 即使資料存儲暫時宕機，它們也會從臨時存儲中提供資料。
- 最後，它們通過從本地資源提供資料來降低網絡成本。

## Why distributed cache? (為什麼要分佈式快取？)
當快取中所需的資料大小增加時，將整個資料存儲在一個系統中是不切實際的。這是因為以下三個原因：

- 它可能是一個潛在的單點故障 (SPOF)。
- 系統是分層設計的，每一層都應該有其快取機制，以確保來自不同層的敏感資料的解耦。
- 在不同位置進行快取有助於減少該層的服務延遲。
在下表中，我們描述了如何通過使用各種技術在不同層進行快取。重要的是要注意，鍵值存儲組件用於各個層。

```
                                         在系統不同層進行快取
System Layer (系統層)    Technology in Use (使用中的技術)                                               Usage (用法)

                       HTTP 快取標頭、Web 加速器、鍵值存儲、CDN 等                                    加速靜態 Web 內容的檢索，並管理會話

Application (應用程式)   Local cache and key-value data store                                         Accelerate application-level computations and data retrieval
                       本地快取和鍵值資料存儲                                                       加速應用程式級別的計算和資料檢索

Database (資料庫)       Database cache, buffers, and key-value data store                            Reduce data retrieval latency and I/O load from database
                       資料庫快取、緩衝區和鍵值資料存儲                                               減少資料檢索延遲和資料庫的 I/O 負載
```

```
除了上面的三個系統層之外，快取還在 DNS 和客戶端技術 (如瀏覽器或終端設備) 中執行。
```

## How will we design distributed cache? (我們將如何設計分佈式快取？)
我們將把設計和強化分佈式快取主要概念的任務分為五個課程：

1. **Background of Distributed Cache (分佈式快取的背景)**：必須建立在設計分佈式快取時做出關鍵決策所需的背景知識。本課程將重溫一些基本但重要的概念。
2. **High-level Design of a Distributed Cache (分佈式快取的高層設計)**：我們將在本課程中構建分佈式快取的高層設計。
3. **Detailed Design of a Distributed Cache (分佈式快取的詳細設計)**：我們將確定我們高層設計的一些限制，並致力於一個可擴展、負擔得起且高性能的解決方案。
4. **Evaluation of a Distributed Cache Design (分佈式快取設計的評估)**：本課程將針對各種非功能需求 (如可擴展性、一致性、可用性等) 評估我們的設計。
5. **Memcached versus Redis (Memcached 與 Redis)**：我們將討論著名的工業解決方案，即 Memcached 和 Redis。我們還將詳細介紹它們並比較它們的功能，以幫助我們了解它們的潛在用例以及它們與我們設計的關係。
