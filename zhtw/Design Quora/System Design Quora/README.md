# System Design: Quora (系統設計：Quora)
## Introduction (介紹)
由於網上有如此多的資訊，找到問題的答案可能會令人望而生畏。這就是為什麼線上資訊共享變得如此普遍。搜尋引擎幫助我們在網路上挖掘資訊。例如，Google 的搜尋引擎足夠智慧，可以通過從網頁中提取資訊來回答問題。雖然搜尋引擎有其優勢，但有時找到我們想要的資訊並不是一個簡單的過程。讓我們看下面的插圖，了解通過搜尋引擎尋求資訊與人相比有何不同。

[比較通過搜尋引擎與人類尋求資訊](./infoseeking.jpg)

上圖描述了通過其他人尋求資訊可能更具指導意義，即使這會花費額外的時間。通過搜尋引擎尋求資訊可能會因為某個主題的內容不可用而導致死胡同。相反，我們可以向其他人提問。

## What is Quora? (什麼是 Quora？)
Quora 是一個社交問答服務，允許使用者向其他使用者提問。創建 Quora 是因為從搜尋引擎提問會得到快速的答案，但資訊膚淺的問題。相反，我們可以詢問公眾，這感覺更像是在對話，並且即使速度較慢，也可以帶來更深入的理解。Quora 讓任何人都可以提問，任何人都可以回答。此外，還有一些領域專家對特定主題有深入的了解，他們偶爾會通過回答問題來分享他們的專業知識。

下圖顯示了使用 Google 對術語“Quora”的全球使用者搜尋趨勢：

[根據 Google 按年份顯示的 Quora 的受歡迎程度](./popularity.jpg)

超過 3 億的月活躍使用者每天在 Quora 上發布與超過 400,000 個主題相關的數千個問題。

在本章中，我們將設計 Quora 並評估它如何滿足功能和非功能需求。

## How will we design Quora? (我們將如何設計 Quora？)
我們將通過將設計問題分為以下四節課來設計 Quora。

1. **Requirements (需求)**：本課將重點關注設計 Quora 的功能和非功能需求。我們還將估算設計系統所需的資源。
2. **Initial design (初步設計)**：我們將建立一個滿足 Quora 所有功能需求的初步設計，並在本課中制定 API 設計。首先，我們將討論系統的構建塊、完成設計所涉及的其他組件、它們的集成和工作流程。
3. **Final design (最終設計)**：在本課中，我們將從確定初步設計的局限性開始。然後，我們將更新我們的最終設計以滿足所有功能和非功能需求，同時解決這些局限性。我們還將關注設計的一些有趣方面，如資料庫的垂直分片。
4. **Evaluation (評估)**：我們將專門針對非功能需求評估我們的設計，並討論其一些權衡。在本課中，我們還將討論一些關於如何提高設計可用性的想法。
