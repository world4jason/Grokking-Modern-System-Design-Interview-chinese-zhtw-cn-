Answers (答案)

```
1
在網址縮短系統的設計中，將定序器的基數更改為 58 的主要原因是：

A)
為了讓生成的短網址更安全。

Explanation (解釋)
安全性與定序器的基數無關。

Your Answer (你的答案)
B)
為了增強生成的短網址的可讀性。

Explanation (解釋)
我們將基數更改為 58 以刪除相似字符。

C)
為了提高系統的可用性。

Explanation (解釋)
可用性與定序器的基數沒有直接對應關係。

D)
為了確保系統的低延遲。

Explanation (解釋)
低延遲與定序器的基數沒有直接對應關係。

```
2
在系統設計階段，以下哪個原因是我們決定使用 MongoDB 的原因？

A)
與讀取相比，它具有更高的寫入吞吐量。

Explanation (解釋)
MongoDB 的情況恰恰相反。

Selected Option (選擇的選項)
B)
它確保並發寫入時的原子性。

所有 NoSQL 資料庫都易於擴展，並且這種比較不是隨時可用的。

3
(選擇所有適用項。) 為了滿足為短鏈接創建自定義別名的功能需求，我們需要在 API 調用的 custom_alias 變量上施加以下哪些限制？

您可以選擇多個正確答案。

Selected Option (選擇的選項)
A)
custom_alias 的長度不應大於短鏈接允許的字符限制。

Explanation (解釋)
在我們的例子中，我們限制為來自 base-58 的 11 個字母數字字符。

B)
使用者必須聲明 custom_alias 變量的值。

Explanation (解釋)
這不是我們設計的系統的要求，因為默認值為 None。

C)
每次使用者創建短鏈接時，單個使用者必須輸入相同的 custom_alias。

Explanation (解釋)
這種可能性但不是要求；我們可以針對自定義網址更新長網址，但這對使用者來說不是強制性的。

Selected Option (選擇的選項)
D)
custom_alias 不應包含已刪除的相似字符。

Explanation (解釋)
只包含允許的 base-58 字符作為 custom_alias 是基本要求。
