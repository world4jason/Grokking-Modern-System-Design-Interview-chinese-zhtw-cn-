# Evaluation of TinyURL's Design (評估 TinyURL 的設計)
## Reviewing the requirements (審查需求)
系統設計的最後階段是根據最初提到的非功能需求對其進行評估。讓我們逐一查看每個指標。

### Availability (可用性)
我們需要為生成新短網址和根據現有短網址進行重定向的使用者提供高可用性。

我們的大多數構建塊，如資料庫、快取和應用伺服器都有內置的複製，可確保可用性和容錯。短網址生成系統也不會影響可用性，因為它依賴於一個易於複製的可用及已用唯一 ID 資料庫。

為了處理災難，我們可以對存儲和應用伺服器執行頻繁的備份，最好每天兩次，因為我們不能冒丟失網址資料的風險。我們可以使用 Amazon S3 存儲服務進行備份，因為它還有助於跨區域複製和恢復。在最壞的情況下，我們可能會丟失 330 萬 (假設每日請求為 660 萬) 個新生成的短網址，這些短網址在特定日期沒有備份。

我們的設計使用全局伺服器負載平衡 (GSLB) 來處理我們的系統流量。它確保了不同全球伺服器之間的智能請求分配，特別是在現場故障的情況下。

我們還限制了來自客戶端的請求，以保護固有的故障點。為了保護系統免受 DoS 攻擊，我們在客戶端和 Web 伺服器之間使用速率限制器來限制每個使用者的資源分配。這將確保良好和流暢的流量流入，並減少對系統資源的利用。

### Scalability (可擴展性)
我們的設計是可擴展的，因為我們的資料可以輕鬆地分發到水平分片的資料庫中。我們可以採用一致性哈希方案來平衡應用層和資料庫層之間的負載。

```
我們在擴展資料庫伺服器時也可以使用基於範圍的分片。但是，如果我們根據預定義的範圍對資料庫進行分區，由於每個範圍內網址的分佈不均，可能會導致分區不平衡。這方面的一個例子可能是基於網址首字母的分佈。
```

我們選擇 MongoDB 作為映射網址的資料庫，也有助於水平擴展。選擇 NoSQL 資料庫的一些有趣原因是：

1. 當使用者在未登錄的情況下訪問我們的系統時，我們的系統不會保存 UserID。由於我們對存儲資料值很靈活，而且這更符合 NoSQL 資料庫提供的模式靈活性，因此在我們的設計中使用它是可取的。

2. 水平擴展傳統關係資料庫是一個令人生畏的過程，並對滿足我們的可擴展性需求提出了挑戰。我們希望在多個伺服器上擴展並自動分發我們系統的資料。對於這個需求，NoSQL 資料庫最能滿足我們的目的。

此外，定序器設計中可用的大量唯一 ID 也確保了我們系統的可擴展性。

### Readability (可讀性)
使用 base-58 編碼器而不是 base-64 編碼器增強了我們系統的可讀性。我們將可讀性分為兩部分：

- **Distinguishable characters (可區分字符)**：消除了像 0 (零)、O (大寫 o)、I (大寫 i) 和 l (小寫 L) 這樣的字符，排除了將一個字符誤認為另一個相似字符的可能性。
- **Non-alphanumeric characters (非字母數字字符)**：像 + (加號) 和 / (斜槓) 這樣的非字母數字字符也被消除，以便在短網址中只有字母數字字符。其次，它還有助於避免其他依賴於系統的編碼，並使網址可隨時用於所有現代文件系統和網址方案。這些字符可能會導致解析期間出現意外行為和輸出。
這種非功能需求增強了我們系統的使用者交互性，並使使用者使用短網址時不易出錯。

從未使用和隨時可用的唯一 ID 池中隨機選擇並將 ID 關聯到每個請求。

### Latency (延遲)
我們的系統通過以下功能確保低延遲：

- 即使是短網址生成過程中最耗時的步驟，即編碼，也只需要幾毫秒。生成短網址的總時間相對較短，確保此過程沒有明顯延遲。

- 我們的系統是重定向密集型的。與讀取相比，在資料庫上寫入是極少的，其性能取決於它如何處理所有重定向請求，與縮短請求相比。我們特意選擇 MongoDB，因為它在讀取密集型任務中具有低延遲和高吞吐量。

- 此外，使用者在接下來幾秒鐘內使用新生成的短網址的概率相對較低。在此期間，同步複製到其他位置是可行的，因此增加了系統對使用者的整體低延遲。

- 在我們的設計中部署分佈式快取還可以確保系統以儘可能小的延遲重定向使用者。

由於這些設計修改，系統享有低延遲和高吞吐量，提供良好的性能。

### Unpredictability (不可預測性)
其中一個需求是使我們系統的短網址不可預測，從而增強我們系統的安全性。

由於定序器按順序生成唯一 ID 並在伺服器之間分配範圍。每個伺服器都有預先分配的唯一 ID 範圍，將它們串行分配給請求將使預測下一個短網址變得容易。為了應對這種情況，我們可以從可用的唯一 ID 中隨機選擇一個唯一 ID，並將其與長網址關聯，包含我們系統的不可預測性。


## Conclusion (結論)
網址縮短系統是一項具有多種優勢的有效服務。我們的網址縮短服務設計簡單，但它滿足了高性能設計的所有需求。我們設計提供的關鍵功能是：

1. 動態短網址範圍
2. 提高可讀性
可能的補充可能是引入 (本地) 鹽以進一步增加設計的不可預測性 (安全性)。
