## Searching (搜尋)
從 Google Maps 中，我們能夠連接片段並應對有效處理大型圖的可擴展性挑戰。世界的圖有許多節點和頂點，遍歷它們非常耗時。因此，我們將整個世界分成更小的片段/子圖來同時處理和查詢它們。分段有助於我們提高系統的可擴展性。

每個片段的大小為 5×5 英里，並包含其中存在的地點列表。我們只搜尋幾個片段來定位附近的目​​的地。我們可以使用給定的位置和定義的半徑來查找所有附近的片段並識別附近的站點。

### Search using segments (使用片段搜尋)
使用者可以選擇一個半徑來搜尋不存在於單個片段中的地點。因此，我們需要通過連接片段來組合多個片段，以查找指定半徑內 (例如，5 英里) 的位置。

首先，我們限制片段的數量。這減少了圖的大小並使搜尋過程可優化。然後，我們識別所有相關位置，計算距搜尋點的距離，並將其顯示給使用者。

## Dynamic segments (動態片段)
我們通過動態調整片段大小來解決片段中地點分佈不均的問題。我們這樣做是透過專注於地點的數量。如果地點數量達到一定限制，我們會將一個片段拆分為另外四個片段。我們假設 500 個地點為我們的限制。在使用這種方法時，我們需要決定以下問題：

我們將如何映射片段？
我們將如何連接到其他片段？
我們使用四元樹 (QuadTree) 來管理我們的片段。每個節點包含一個片段的訊息。如果地點數量超過 500，我們會將該片段拆分為另外四個子節點，並在它們之間分配地點。這樣，葉節點將是那些無法進一步分解的片段。每個葉節點中也會有一個地點列表。
```
四元樹是一種樹資料結構，其中每個內部節點恰好有四個子節點。四元樹是八叉樹的二維模擬，最常用於通過遞歸地將二維空間細分為四個象限或區域來對其進行分區。與葉單元關聯的資料因應用程式而異，但葉單元代表“感興趣的空間訊息單元”。來源：維基百科
```

### Search using a QuadTree (使用四元樹搜尋)
我們從根節點開始搜尋並繼續訪問節點以找到我們想要的片段。我們檢查每個節點看看它是否有更多的子節點。如果一個節點沒有更多的子節點，那麼我們停止搜尋，因為該節點就是我們需要的節點。我們還使用雙向鏈錶將每個子節點與其相鄰節點連接起來。所有父節點的所有子節點都通過雙向鏈接列表連接。此列表允許我們在需要時向前和向後移動查找相鄰片段。識別片段後，我們擁有地點所需的 PlaceID 值，我們可以搜尋資料庫以查找有關它們的更多詳細訊息。

**Question (問題)**

有沒有另一種方法可以找到相鄰的片段？

**Answer (答案)**

我們可以使用父節點的指針來查找相鄰的片段。在每個節點中，我們可以保留一個指向父節點的指針。每個父節點都有指向其子節點的指針，因此我們可以使用這些指針來查找相鄰的葉節點。我們可以通過父指針向上擴展我們的搜尋。

### Storage space estimation for QuadTrees (四元樹的儲存空間估算)
讓我們計算保存四元樹所需的儲存空間：

- 我們在節點中存儲每個地點的 PlaceID、經度和緯度。這些值中的每一個大小為 8 字節。對於 5 億個地點，我們需要以下數量的儲存空間來存儲所有地點：

- 我們在單個節點中將有 500 個地點。因此，對於 5 億個地點，我們將需要 500 M/500 = 100 萬個葉節點。

擁有 100 萬個葉節點的四元樹大約有內部節點 (直到葉級別的所有節點) 的 1/3 的葉節點，並且每個內部節點都有四個指向其子節點的指針。如果我們假設每個指針為 8 字節，那麼我們將需要 1M * 1/3 * 4 * 8 = 10.67 MB 的空間用於內部節點。
```
Source: https://tildesites.bowdoin.edu/~ltoma/teaching/cs3225-GIS/fall16/Lectures/gis_qdt1.pdf
我們可以通過將 12GB 和 10.67MB 相加得到存儲所有內部節點所需的總空間，即大約 12.01GB。

我們可以輕鬆地將四元樹存儲在伺服器上。

讓我們嘗試以下計算器來計算四元樹所需的儲存空間：

Total Number of Places (Millions) (地點總數 (百萬))                    500
Total Space Needed to Store All Places (GB) (存儲所有地點所需的總空間 (GB))           12
Limit of Places for Each Segment (每個片段的地點限制)                     500
Number of Segments (Millions) (片段數量 (百萬))                          1
Number of Pointers to Hold Children Pointers (持有子指針的指針數量)           4
Size of Each Pointer (Bytes) (每個指針的大小 (字節))                           8
Total Space to Store All Internal Nodes (MB) (存儲所有內部節點的總空間 (MB))         10.67
Total Space to Store QuadTrees (GB) (存儲四元樹的總空間 (GB))                  12.01
```

### Data partitioning (資料分區)
考慮到每年 20% 的增長，地點的數量將會增加。我們可以根據以下基礎對資料進行分區：

1. **Regions (區域)**：我們可以根據郵政編碼將我們的地點劃分為區域。這樣，屬於特定區域的所有地點都存儲在單個節點上。我們將區域訊息與地點一起存儲，以便我們也可以根據區域進行查詢。我們可以使用使用者的區域來查找該特定區域的地點。

這種資料分區帶來了一些挑戰。例如，如果某個區域在旅遊旺季變得很受歡迎，它可能會影響我們系統的效能。我們可能會在伺服器上有大量查詢，這可能會導致對使用者查詢的響應緩慢。

2. **PlaceID**：我們可以根據 PlaceID 而不是區域來分區資料，以避免在熱門季節或高峰時段查詢過載。我們可以使用鍵值存儲來存儲地點。在這種情況下，鍵是 PlaceID，值包含存儲該地點的伺服器。這將使獲取地點的過程更加高效。

因此，我們將選擇基於地點進行分區。此外，我們還將為熱門地點使用快取。快取將包含有關該特定地點的訊息。

### Ensure availability (確保可用性)
考慮一個場景，同一半徑內的多個人發出搜尋請求。如果我們只有一個四元樹，它會影響使用者的可用性。所以，我們不能依賴單一的四元樹。為了解決這個問題，我們在多個伺服器上複製我們的四元樹以確保可用性。這使我們能夠分發讀取流量並減少響應時間。四元樹建立在伺服器上，因此我們可以使用伺服器 ID 作為鍵來標識存在四元樹的伺服器。值是四元樹持有的地點列表。鍵值存儲便於我們在丟失四元樹時重建它。
```
Question
問題
領導者-追隨者方法將如何幫助我們進行複製？

Answer
答案
我們將有一個領導者和兩個追隨者。領導者將擁有四元樹，並處理所有寫入請求。它將同步更新追隨者關於四元樹所做的任何更改，因此可能會出現延遲。追隨者將處理所有讀取請求。如果追隨者死亡，我們將選擇另一個追隨者並將資料複製給它。如果領導者倒下，我們將選擇任何追隨者介入作為領導者。這樣，我們就能夠將我們的四元樹複製到三台伺服器上。
```

### Insert a new place (插入新地點)
我們將新地點插入資料庫以及我們的四元樹中。如果四元樹分佈在不同的伺服器上，我們會找到新地點的片段，然後將其添加到該片段中。如果需要，我們會拆分片段並相應地更新四元樹。

### Rank popular places (排名熱門地點)
我們需要一個服務，即評級計算器，它計算服務的整體評級。我們可以將地點的評級以及地點的 ID、緯度和經度存儲在資料庫和四元樹中。四元樹返回給定半徑內的前 50 或 100 個熱門地點。聚合服務確定實際的熱門地點並將其返回給使用者。
```
注意：我們不希望評級在數小時內更新，因為四元樹或資料庫中的這種頻繁更改可能會很昂貴。我們每天更新一次，此時負載最小。
## Finalized design (最終設計)
我們在設計中添加了一些新組件。我們引入了快取來存儲熱門地點。這使我們能夠更快地獲取地點。此外，我們還添加了一個評級計算器，可根據評級對地點進行排序。這將增強使用者體驗，因為評級高的地點將首先顯示。

## Evaluation (評估)
讓我們看看我們的系統設計如何滿足我們的需求。

- **Availability (可用性)**：我們將資料劃分為更小的片段，而不是處理包含世界地圖上所有地點的巨大資料集。這使我們的系統高度可用。我們還使用鍵值存儲複製四元樹資料以確保可用性。
- **Scalability (可擴展性)**：我們將整個世界分成更小的動態片段。這使我們能夠在特定半徑內搜尋地點並縮短搜尋區域。然後我們使用四元樹，其中每個子節點包含一個片段。在添加或刪除地點時，我們可以重組我們的四元樹。因此，我們能夠使我們的系統具有可擴展性。
- **Performance (效能)**：我們通過使用快取減少了延遲。我們快取了所有著名的和熱門的地點，因此請求時間被最小化。
- **Consistency (一致性)**：使用者對有關地點、評論和照片的資料具有一致的視圖，因為我們使用了可靠且容錯的資料庫，如鍵值存儲和關係資料庫。

## Summary (總結)
基於鄰近的伺服器允許使用者搜尋特定地點或附近的地點。世界的地圖資料是巨大的，將其劃分為片段並找到特定片段本身就是一個挑戰。因此，我們使用四元樹來優化我們的搜尋，並以最小的延遲為使用者提供地點列表。
