# Examples of Resource Estimation (資源估算範例)

## Introduction (簡介)
既然我們已經為資源估算奠定了基礎，讓我們利用我們的背景知識來估算伺服器、儲存和頻寬等資源。在下文中，我們考慮一個場景和一個服務，做出假設，並根據這些假設進行估算。讓我們直接開始吧！

## Number of servers required (所需伺服器數量)
讓我們對一個類似 Twitter 的服務做出以下假設。

有 5 億 (500 M) 使用者日活躍數 (DAU)。

單個使用者平均每天發出 20 個請求。

回想一下，單個伺服器可以處理 8,000 RPS。

每秒總請求數 500M x 20/86400 = 115K requests per second，這是我們系統的 RPS。

對於伺服器數量，(Number of Request/sec) / RPS of server = 115k/8k = 15  台伺服器來處理所有請求。
```

[估算伺服器數量](./estimating_the_number_of_servers.jpg)

確實，上面的數字看起來不對。如果我們只需要 15 台商用伺服器來服務 5 億每日使用者，那麼為什麼大型服務在資料中心使用數百萬台伺服器？主要原因是 RPS 不足以估算提供服務所需的伺服器數量。此外，我們在上面的計算中做出了一些基本假設。其中一個假設是請求僅由一台伺服器處理。實際上，請求會通過可能與應用伺服器互動的 Web 伺服器，應用伺服器也可能從儲存伺服器請求資料。每個伺服器處理每個請求可能需要不同的時間。此外，每個請求可能會根據資料中心、應用程式和請求本身的狀態得到不同的處理。請記住，我們在資料中心內有各種伺服器來提供各種服務。

因此，我們通過描述伺服器在給定的一天處理多少客戶端來估算伺服器數量：
在這種情況下，它等於 500M / 8000 = 62,500

注意：這可能不是一個準確的估算，但這是一個現實的估算。因此，我們在設計問題中使用這種方法來估算伺服器數量。非正式地說，上面給出的方程式假設一台伺服器可以處理 8,000 個使用者。我們在本課程的其餘部分也使用這個參考。
```

## Storage requirements (儲存需求)

在本節中，我們嘗試通過使用 Twitter 作為範例來了解如何進行儲存估算。我們估算 Twitter 一年內新推文所需的儲存空間。讓我們首先做出以下假設：
我們總共有 2.5 億 (250 M) 使用者日活躍數 (DAU)。

每個使用者每天發佈三條推文。

10% 的推文包含圖片，而 5% 的推文包含影片。任何包含影片的推文將不包含圖片，反之亦然。

假設平均一張圖片為 200 KB，一段影片為 3 MB。

推文文字及其元數據 (metadata) 在資料庫中總共需要 250 Bytes 的儲存空間。
```

那麼，將需要以下儲存空間：

[估算儲存需求](./estimating_storage_req.jpg)

總推文數：250M x 3 = 750M x 10^6 條推文每天
一天推文所需的儲存空間：750 x 10^6 x 250 B = 187.5 GB
一天 10% 圖片所需的儲存空間：(750 x 10^6 x 10/100) x 200 x 10^3 B=15TB
一天 5% 影片內容所需的儲存空間：(750 x 10^6 x 5/100) x 3 x 10^6 B=112.5TB
```

一天所需的總儲存空間 = 0.1875 TB + 15 TB + 112.5 TB = 大約 128TB
一年所需的儲存空間 = 365 x 128 TB = 46.72 PB
[Twitter 一年的總儲存量](./total_storage_yearly.jpg)


## Bandwidth requirements (頻寬需求)

為了估算服務的頻寬需求，我們使用以下步驟：

估算服務每天的傳入數據量。

估算服務每天的傳出數據量。

通過將傳入和傳出數據除以一天的秒數來估算 Gbps (每秒千兆位元) 的頻寬。

### Incoming traffic (傳入流量)：讓我們繼續之前的 Twitter 範例，它每天需要 128 TB 的儲存空間。因此，傳入流量應支援以下每秒頻寬：
128 x 10^12 / 86400 x 8 = 大約 12 Gbps
```

注意：我們乘以 8 是為了將 Bytes(B) 轉換為 bits(b)，因為頻寬是以每秒位元數 (bits per second) 來衡量的。
```

### Outgoing traffic (傳出流量)：假設單個使用者每天觀看 50 條推文。考慮到影片和圖片的比例分別為 5% 和 10%，對於這 50 條推文，2.5 條推文將包含影片內容，而 5 條推文將包含圖片。考慮到有 2.5 億 (250 M) 活躍每日使用者，我們得出以下估算：

[估算頻寬需求](./estimating_bandwidth_req.jpg)

250M x 50 推文 = 每天觀看 125 億條推文 (12.5 billion)
每秒觀看的推文數：12.5 / 86400 = 145 x 10^3 推文每秒
推文頻寬：145 x 10^3 x 250 x 8 bits = 大約 0.3 Gbps  (一條推文等於 250 bytes)。
每秒推文中 10% 圖片的頻寬：145 x 10^3 x 10/100 x 200 x 10^3 x 8 bits = 23.2 Gbps
每秒 5% 影片推文的頻寬： 145x 10^3 x 5/100 x3 x10^6 x 8 bits = 174 Gbps

所需的總傳出流量將等於：0.3 + 23.2 + 174 = 大約 197.5 Gbps。
Twitter 將需要總共 12 Gbps 的傳入流量和 197.5 Gbps 的傳出流量，假設上傳的內容未經壓縮。總頻寬需求 = 12 + 197.5 = 209.5 Gbps
