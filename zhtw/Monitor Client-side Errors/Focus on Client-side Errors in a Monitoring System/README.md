# Focus on Client-side Errors in a Monitoring System (專注於監控系統中的客戶端錯誤)
## Client-side errors (客戶端錯誤)
在分佈式系統中，客戶端通常通過 HTTP 請求訪問服務。如果請求處理失敗，我們可以監控我們的 Web 和應用程式伺服器日誌。如果多個請求失敗，我們可以觀察到內部錯誤 (錯誤 500) 的激增。

那些根本原因在客戶端的錯誤很難響應，因為服務對客戶端系統幾乎沒有洞察力。我們可能會嘗試尋找與平均水平相比的負載下降，但這樣的圖表通常很難。由於諸如負載意外變化或一小部分客戶端群體受到影響等因素，它可能會出現誤報和漏報。

有許多因素可能導致故障，導致客戶端無法訪問伺服器。其中包括以下內容：

- DNS 名稱解析失敗。
- 從客戶端到服務提供商的路徑上的任何路由故障。
- 第三方基礎設施的任何故障，例如中間盒和內容交付網絡 (CDN)。

## Failures due to a routing bug (由於路由錯誤導致的故障)
讓我們看一個現實世界的錯誤示例，該錯誤影響了大量服務客戶，但服務並未立即意識到這一點。

Google 的一個對等 ISP 意外發布了它不應該發布的 Internet 路由。結果，許多 Google 客戶的流量開始通過非預期的 ISP 路由，並且無法到達 Google。客戶很沮喪，因為他們無法訪問 Google，而 Google 可能沒有立即意識到此類問題，因為這些問題並未發生在其基礎設施上。

[BGP 洩漏](./bgp_leak.jpg)

上述洩漏並非獨一無二。類似的問題不斷出現。另一起此類洩漏發生在 2021 年 4 月 16 日，當時一個 AS 錯誤地宣布了超過 30,000 個 BGP 前綴。這導致進入其網絡的入站流量激增 13 倍。但是，觀察到湧入增加，問題得到了解決。

受影響服務的監控系統可能無法立即捕獲上述事件。監控此類情況至關重要，以便應用程式可供其所有客戶使用。因此，在接下來的課程中，我們將介紹幫助我們監控上述情況的方法。
