# System Design: Google Maps (系統設計：Google Maps)
## What is Google Maps? (什麼是 Google Maps？)
讓我們通過假設我們想從一個地方旅行到另一個地方來介紹這個問題。以下是我們可能想知道的事情：

- 根據我們使用的車輛類型，到達目的地的最佳路徑是什麼？
- 每條路徑有多少英里？
- 每條路徑需要多少時間才能到達目的地？
地圖應用程式 (如 Google Maps 或 Apple Maps) 使用戶能夠輕鬆回答上述所有問題。下圖顯示了 Google Maps 計算的從“美國洛杉磯”到“美國紐約市”的路徑。

## When do we use a maps service? (我們什麼時候使用地圖服務？)
個人和組織依靠位置資料在世界各地導航。地圖在這些情況下有幫助：

- 個人可以快速找到新地點的位置和路線，而不是浪費時間和旅行成本 (如汽油)。
- 個人使用地圖查看預計到達時間 (ETA) 以及基於當前交通資料的最短路徑。
- 許多現代應用程式嚴重依賴地圖，例如叫車服務、自動駕駛車輛和徒步旅行地圖。例如：
  - Waymo 的自動駕駛汽車系統使用 Google Maps 高效、快速、安全地導航。
  - Uber 使用 Google Maps 作為其應用程式的一部分來協助司機，並為客戶提供行程的視覺化表示。
- 基於路線和物流的公司減少了交付所需的時間。通過利用地圖獨特的實時和歷史交通資料，它通過減少汽油使用和交通堵塞時間來最大限度地降低交付的總成本。
2022 年，超過 500 萬家企業正在使用 Google Maps。它為企業提供了一個 API，以便在其應用程式中使用地圖系統。

## How will we design Google Maps? (我們將如何設計 Google Maps？)
我們將 Google Maps 的設計分為五節課：

1. **Requirements (需求)**：在本課中，我們將列出 Google Maps 系統的功能和非功能需求。我們還將確定設計此類系統所涉及的挑戰。最後，我們將估算為數百萬使用者查詢所需的伺服器和頻寬等資源。
2. **Design (設計)**：本課包括像 Google Maps 這樣的系統的高層和 API 設計。我們將描述系統的服務和工作流程。
3. **Meeting the challenges (應對挑戰)**：我們將討論如何克服我們在需求課中強調的挑戰。
4. **Detailed design (詳細設計)**：基於對挑戰的解決方案，我們將改進我們先前的設計，並詳細闡述其不同方面。我們將描述詳細設計，包括儲存模式。
5. **Evaluation (評估)**：本課解釋我們設計的 Google Maps 系統如何滿足所有需求。

讓我們從理解設計像 Google Maps 這樣的系統的需求開始。
