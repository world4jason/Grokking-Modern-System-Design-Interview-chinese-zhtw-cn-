# Challenges of Google Maps’ Design (Google Maps 設計的挑戰)

## Meeting the challenges (迎接挑戰)
我們在介紹課中列出了兩個挑戰：可擴展性和 ETA 計算。讓我們看看如何應對這些挑戰。

### Scalability (可擴展性)
可擴展性是指高效處理巨大道路網路圖的能力。我們有一個包含數十億頂點和邊的圖，主要的挑戰是低效的加載、更新和執行計算。例如，我們必須遍歷整個圖才能找到最短路徑。這導致使用者的查詢時間增加。那麼，這個問題的解決方案可能如同？

其想法是將大型圖分解為較小的子圖或分區。子圖可以並行處理和查詢。因此，圖的構建和查詢處理時間將大大減少。所以，我們將地球劃分為稱為段 (segments) 的小部分。每個段對應一個子圖。

#### Segment (段)
段是我們可以輕鬆工作的的一小塊區域。在這些段中尋找路徑之所以有效，是因為段的道路網路圖很小，可以輕鬆加載到主記憶體中、更新和遍歷。例如，一個城市可以分為數百個段，每個段長寬為 5x5 英里。

Traversing (遍歷) 是訪問圖頂點以到達特定頂點。
```

注意：段不一定是正方形。它也可以是多邊形。但是，為了便於解釋，我們假設它是正方形段。
每個段有四個坐標，有助於確定使用者所在的段。每個坐標由兩個值組成，緯度和經度。

[將地球劃分為小段，每個段有四個帶有緯度和經度值的坐標](./segment.jpg)

讓我們談談在一個段內的兩個位置之間尋找路徑。我們有一個代表該段道路網路的圖。每個路口/交叉口充當一個頂點，每條道路充當一條邊。該圖是加權的，每條邊上可能有多個權重——例如距離、時間和流量——以找到最佳路徑。對於給定的起點和終點，可能有多條路徑。我們可以使用該段圖上的任何圖演算法來找到最短路徑。最常見的最短路徑演算法是 Dijkstra 演算法。

傳統的 Dijkstra 演算法執行引導搜尋以找到最短路徑。但是，它的代價是查詢時間增加。我們必須對查詢時間設定限制，因為我們不想讓使用者等待太久才能獲得結果。所以，我們將在給定的時間成本內尋找最佳路徑。

A* 演算法是 Dijkstra 演算法的擴展，它使用啟發式方法來指導搜尋。A* 不是尋找最短路徑，而是尋找通過最小化以下函式計算出的最佳路徑。

f(n)=g(n)+h(n)

這裡，n 是路徑上的下一個節點，g(n) 是從起始節點到 n 的路徑成本，h(n) 是估計從 n 到目標的最便宜路徑成本的啟發式函式。
```

注意：有一些演算法是專門為道路網路設計的，重點是實現更短的查詢時間。這些演算法是 A*、Arc flags、contraction hierarchies、transit node routing、reach-based routing 和 hub labeling。

在段的圖上運行最短路徑演算法後，我們將演算法的輸出儲存在分散式儲存中以避免重新計算，並快取最常請求的路線。演算法的輸出是圖中每兩個頂點之間的最短距離 (以公尺或英里為單位)、通過最短路徑行駛所需的時間以及沿每條最短路徑的頂點列表。以上所有處理 (在段圖上運行最短路徑演算法) 都是離線完成的 (不在使用者的關鍵路徑上)。

[在段內尋找頂點之間的路徑](./path.jpg)

上圖顯示了我們如何找到兩點之間以英里為單位的最短距離。例如，點 A 和 D 之間的最小距離 (m) 是 11 英里，路徑為 A->C->D。它的 ETA 為 15 分鐘。

我們已經找到了兩個頂點之間的最短路徑。如果我們必須找到位於邊上的兩點之間的路徑怎麼辦？我們要做的是找到點所在的邊的頂點，計算點到已識別頂點的距離，並選擇使起點和終點之間總距離更短的頂點。從起點 (和終點) 到最近頂點的距離使用緯度/經度值近似計算。

[選擇位於邊上的點之間的路徑](./selection.jpg)

我們能夠找到段內的最短路徑。讓我們看看當起點和終點屬於兩個不同的段時會發生什麼，以及我們如何連接這些段。

#### Connect two segments (連接兩個段)
每個段都有唯一的名稱和邊界坐標。我們可以輕鬆識別哪個位置 (緯度，經度) 位於哪個段中。給定起點和終點，我們可以找到它們所在的段。對於每個段，都有一些邊界邊，我們稱之為出口點 (exit points)。在下圖中，我們有四個出口點，S4E1、S4E2、S4E3 和 S4E4。

注意：除了段內的頂點外，我們還將段的出口點視為頂點，並計算這些出口點的最短路徑。因此，對於每個段，除了計算從出口點到段內頂點的最短路徑外，我們還計算出口點之間的最短路徑。每個頂點從段出口點的最短路徑資訊都被快取。
[通過將段的出口點視為頂點來連接段](./connection.jpg)


出口點連接相鄰的段並在它們之間共享。在上圖中，每個出口點都連接兩個段，並且每個都在兩個段之間共享。例如，出口點 S4E1 也是 S1 的出口點。擁有了每個段的所有出口點，我們可以連接這些段並找到不同段中兩點之間的最短距離。在連接段時，我們不關心內部段圖。我們只需要出口點和關於出口點的快取資訊。我們可以將其可視化為由出口頂點組成的圖，如下圖所示。

[由出口點組成的圖，其中連接出口點的線實際上不是直線。兩個出口點之間可能有很多頂點](./exit.jpg)

由於我們無法對全球所有段運行最短路徑演算法，因此確定我們在跨段旅行時需要考慮多少個段對於我們的演算法至關重要。兩地之間的空中距離用於限制段的數量。有了起點和終點，我們可以使用半正矢公式 (haversine formula) 找到它們之間的空中距離。

### ETA computation (ETA 計算)

為了以合理的準確度計算 ETA，我們通過發布-訂閱系統從導航服務收集實時位置資料 ((userID, timestamp, (latitude, longitude)))。利用位置資料流，我們可以計算和預測不同道路上的交通模式。我們可以計算的一些事情是：

- 不同路線或道路上的交通 (高/中/低)。
- 車輛在不同道路上的平均速度。
- 類似交通模式在路線或道路上重複的時間間隔。例如，X 高速公路在上午 8 點到 10 點之間交通繁忙。

上述資訊有助於我們提供更準確的 ETA。例如，如果我們知道某條特定道路在特定時間交通繁忙，那麼 ETA 也應該比平時長。

在本課中，我們研究了如何通過段和使用實時資料的 ETA 計算來應對可擴展性挑戰。在下一課中，我們將更詳細地討論設計。
