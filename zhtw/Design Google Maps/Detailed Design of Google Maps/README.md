# Detailed Design of Google Maps (Google Maps 詳細設計)

## Segment setup and request handling (段設定和請求處理)
本節將描述段資料如何儲存在資料庫中，以及如何使用已經儲存的資料處理使用者請求。

從儲存模式開始，我們討論如何新增段並將其託管在伺服器上，以及如何處理使用者請求。

### Storage schema (儲存模式)
我們為每個段儲存以下資訊：

**Key-value store (鍵值儲存):**

段的 ID。
託管該段的 serverID。
實際上，每個段都是一個多邊形，因此我們儲存邊界坐標 (緯度/經度)，可能作為一個列表。
相鄰段的段 ID 列表。

**Graph database (圖資料庫)**

段內的道路網路以圖的形式呈現。

[儲存模式](./storage.jpg)

**Relational DB (關聯式資料庫)**

我們儲存資訊以確定一天中的特定時間道路是否擁堵。這以後有助於我們決定是否根據實時資料更新圖 (權重)。

- edgeID 標識邊。
- hourRange 告訴我們一天中的哪個小時道路上有典型的路況 (非高峰時段)。
- rush 是一個布林值，描述特定道路在特定時間是否有擁堵。

注意：segID、serverID 和 edgeID 是由唯一 ID 生成器生成的唯一 ID (有關詳細資訊，請參見序列生成器課程)。
### Design (設計)
下圖由兩個工作流程組成。一個是將段新增到地圖並將其託管在伺服器上，另一個是顯示如何處理查找兩點之間路徑的使用者請求。

[工作流程 1) 新增段 (黃色)，工作流程 2) 處理使用者請求 (藍色)](./design.jpg)

**Add segment (新增段)**

1. 每個段都有其緯度/經度邊界坐標及其道路網路圖。
2. 段添加器 (segment adder) 與段資訊一起處理新增段的請求。段添加器使用唯一 ID 生成器系統為每個段分配唯一 ID。
3. 為段分配 ID 後，段添加器將段資訊轉發給伺服器分配器 (server allocator)。
4. 伺服器分配器為段分配一個伺服器，在該伺服器上託管該段圖，並將 serverID 返回給段添加器。
5. 將段分配給伺服器後，段添加器將段到伺服器的映射儲存在鍵值儲存中。它有助於找到合適的伺服器來處理使用者請求。它還將每個段的邊界緯度/經度坐標儲存在單獨的鍵值物件中。

**Handle the user’s request (處理使用者請求)**

1. 使用者提供起點和終點，以便我們的服務可以找到它們之間的路徑。
2. 起點和終點的緯度和經度是通過分散式搜尋確定的。
3. 起點和終點的緯度/經度傳遞給圖處理服務，該服務從鍵值儲存中查找起點和終點緯度/經度所在的段。
4. 找到段 ID 後，圖處理服務從鍵值儲存中查找託管這些段的伺服器。
5. 圖處理服務連接到相關伺服器以查找起點和終點之間的最短路徑。如果起點和終點屬於同一個段，則圖處理服務僅在單個段上運行查詢即可返回最短路徑。否則，它將連接來自不同伺服器的段，正如我們在上一課中看到的那樣。

## Improve estimations using live data (使用實時資料改進估算)
本節描述我們如何使用實時資料提高 ETA 估算的準確性。如果我們有一系列針對不同設備的位置資料，我們可以找到移動模式並執行分析以預測可能影響使用者行程的各種因素。Google Maps 使用 GPS、Wi-Fi 和蜂窩訊號塔的組合來跟蹤使用者的位置。為了收集這些資料，我們的地圖系統伺服器需要與所有開啟位置的設備保持持久連接。下面，我們討論涉及使用實時資料改進估算過程的工具、技術和組件。

- **WebSocket** 是一種類通訊協議，允許使用者和伺服器進行雙向互動式通訊會話。這有助於使用者和伺服器之間的資料實時傳輸。

- **Load balancer (負載平衡器)** 平衡不同伺服器之間的連接負載，因為每個伺服器的 WebSocket 連接數有限制。它將一些設備連接到伺服器 1，一些連接到伺服器 2，依此類推。

[對實時位置資料執行分析以使地圖保持最新狀態並改進 ETA 估算](./analysis.jpg)

- **Pub-sub system (發布-訂閱系統)** 從所有伺服器收集位置資料流 (設備、時間、位置)。來自發布-訂閱的位置資料由像 Apache Spark 這樣的資料分析引擎讀取。資料分析引擎使用資料科學技術——如機器學習、集群等——來測量和預測道路上的交通、識別聚集、熱點、事件、發現新道路等。這些分析有助於我們的系統改進 ETA。

注意：交通量、路況和熱點直接影響平均行駛速度，這最終會影響使用者的 ETA。
- 資料分析引擎將分析資料發布到新的發布-訂閱主題。

- **Map update service (地圖更新服務)** 偵聽來自發布-訂閱主題的分析更新。如果識別出新道路或圖的邊上的權重 (平均速度 (交通、路況)) 發生變化，它會更新段圖。根據位置，我們知道由哪個段進行更新。我們從鍵值儲存中找到放置該段的路由伺服器，並更新該伺服器上的圖。

Question (問題)
許多交通狀況是暫時的 (如在訊號燈處停車)，因此頻繁更新圖無法很好地擴展，因為它需要過多的處理。這個問題的解決方案可能如同？

Answer (答案)
為了檢測暫時和正常情況，我們保留所有相關資料 (權重) 的兩個副本：一個用於正常情況，另一個用於暫時情況。這樣，我們就不必進行過多的處理。
