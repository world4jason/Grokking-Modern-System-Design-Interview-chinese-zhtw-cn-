# Introduction to Building Blocks for Modern System Design (現代系統設計構建塊簡介)

## The bottom-up approach for modern system design (現代系統設計的自下而上方法)
系統設計問題通常有一些相似之處，儘管具體細節通常是獨特的。我們將跨設計問題的這些相似之處提取為我們將涵蓋的基本構建塊。構建塊的一個例子是負載平衡組件，我們可能會以某種方式在每個設計問題中使用它。

分離構建塊的目的是徹底討論它們的設計一次。這意味著以後我們可以在任何地方使用它們，而無需再次詳細介紹它們。我們可以將構建塊視為構建更有效、更有能力的系統的磚塊。

我們討論的許多構建塊也可用於公共雲中的實際使用，例如 Amazon Web Services (AWS)、Azure 和 Google Cloud Platform (GCP)。我們可以使用這些構造來構建系統以進一步鞏固我們的理解。(我們不會在本課程中構建系統，但我們將其留作有興趣的學習者的練習。)

我們將詳細討論以下構建塊：

### 1. Domain Name System (網域名稱系統)
此構建塊專注於如何為通過不同網際網路協定連接到網際網路的電腦設計分層和分散式命名系統。
[網域名稱系統](./dns.jpg)

### 2. Load Balancers (負載平衡器)
在這裡，我們將了解負載平衡器的設計，它用於在可用伺服器池中公平地分發傳入的客戶端請求。它還可以減少負載並繞過故障伺服器。
[負載平衡器](./load_balancer.jpg)

### 3. Databases (資料庫)
此構建塊使我們能夠結合不同的資料處理程序來儲存、檢索、修改和刪除資料。在這裡，我們將討論資料庫類型、複製、分區和分散式資料庫的分析。
[資料庫](./db.jpg)

### 4. Key-Value Store (鍵值儲存)
它是一種非關聯式資料庫，以鍵值對的形式儲存資料。在這裡，我們將解釋鍵值儲存的設計以及重要概念，例如實現可擴展性、持久性和可配置性。
[鍵值儲存](./kv.jpg)

### 5. Content Delivery Network (內容傳遞網路)
在本章中，我們將設計一個內容傳遞網路 (CDN)，用於保存病毒式內容，如影片、圖片、音訊和網頁。它有效地向終端使用者傳遞內容，同時減少延遲和資料中心的負擔。
[內容傳遞網路](./cdn.jpg)

### 6. Sequencer (定序器)
在此構建塊中，我們將專注於唯一 ID 生成器的設計，主要重點是保持因果關係。它還解釋了三種生成唯一 ID 的不同方法。
[定序器](./sequencer.jpg)

### 7. Service Monitoring (服務監控)
監控系統在分散式系統中至關重要，因為它們有助於分析系統並在發生問題時提醒利益相關者。監控通常有助於獲得早期預警系統，以便系統管理員可以在即將發生的問題變成巨大問題之前採取行動。在這裡，我們將構建兩個監控系統，一個用於伺服器端錯誤，另一個用於客戶端錯誤。
[服務監控](./service_monitor.jpg)

### 8. Distributed Caching (分散式快取)
在此構建塊中，我們將設計一個分散式快取系統，其中多個快取伺服器協調以儲存頻繁存取的資料。
[分散式快取](./distributed_caching.jpg)

### 9. Distributed Messaging Queue (分散式訊息佇列)
在此構建塊中，我們將專注於由多個伺服器組成的佇列的設計，該佇列用於稱為生產者和消費者的互動實體之間。它有助於解耦生產者和消費者，導致獨立的可擴展性，並增強可靠性。
[分散式訊息佇列](./distributed_message_queue.jpg)

### 10. Publish-Subscribe System (發布-訂閱系統)
在此構建塊中，我們將專注於設計一種稱為發布-訂閱系統的非同步服務對服務通訊方法。它在無伺服器、微服務架構和資料處理系統中很受歡迎。
[發布-訂閱系統](./pub_sub_sys.jpg)

### 11. Rate Limiter (速率限制器)
在這裡，我們將設計一個系統，根據預定義的限制限制服務的傳入請求。它通常用作服務的防禦層，以避免其過度使用——無論是有意還是無意的。
[速率限制器](./rate_limiter.jpg)

### 12. Blob Store (Blob 儲存)
此構建塊專注於非結構化資料的儲存解決方案——例如，多媒體檔案和二進位可執行檔。
[Blob 儲存](./blob_store.jpg)

### 13. Distributed Search (分散式搜尋)
搜尋系統接受來自使用者的查詢並在幾秒鐘或更短的時間內返回相關內容。此構建塊專注於三個不可或缺的組件：爬取 (crawl)、索引 (index) 和搜尋 (search)。
[分散式搜尋](./distributed_search.jpg)

### 14. Distributed Logging (分散式日誌記錄)
日誌記錄是一種耗時且緩慢的 I/O 密集型操作。在這裡，我們將設計一個允許分散式系統中的服務有效地記錄其事件的系統。該系統將具有可擴展性和可靠性。
[分散式日誌記錄](./distributed_logging.jpg)

### 15. Distributed Task Scheduling (分散式任務排程)
我們將設計一個分散式任務排程系統，在任務和資源之間進行調解。它智慧地將資源分配給任務，以滿足任務級和系統級目標。它通常用於卸載後台處理以非同步完成。
[分散式任務排程](./distributed_task_scheduling.jpg)

### 16. Sharded Counters (分片計數器)
此構建塊展示了一個高效的分散式計數系統，以處理數百萬個並發讀取/寫入請求，例如名人推文上的喜歡 (likes)。
[分片計數器](./shared_counter.jpg)

## Conventions (約定)
為了解說，每當我們設計一個構建塊 (和一個設計問題) 時，我們都會使用“需求 (Requirements)”部分。“需求”部分將突顯我們期望從開發的設計中獲得的可交付成果。“需求”將有兩個子類別：

Functional requirements (功能需求)：這些代表設計系統的使用者將能夠使用的功能。例如，系統將允許使用者使用搜尋欄搜尋內容。

Non-functional requirements (NFRs) (非功能需求)：非功能需求是系統使用者認為系統可用的標準。NFR 可能包括高可用性、低延遲、可擴展性等需求。
