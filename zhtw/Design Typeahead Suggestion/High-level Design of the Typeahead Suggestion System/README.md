# High-level Design of the Typeahead Suggestion System (預輸入建議系統的高層設計)

## High-level design (高層設計)
根據我們的要求，系統不僅應該以最小的延遲實時建議查詢，還應該將新的搜尋查詢儲存在資料庫中。這樣，使用者就可以獲得基於熱門和最近搜尋的建議。

我們提出的系統應該做以下事情：

- 根據使用者的搜尋歷史提供建議。
- 將所有新的和趨勢查詢儲存在資料庫中，以將它們包含在建議列表中。
當使用者開始輸入查詢時，每個輸入的字元都會到達其中一個應用程式伺服器。假設我們有一個 suggestions service (建議服務)，它從快取 Redis 中獲取前十個建議，並將它們作為響應返回給客戶端。除此之外，假設我們還有另一個稱為 assembler (組裝器) 的服務。組裝器收集使用者搜尋，應用一些分析來對搜尋進行排名，並將它們儲存在分佈在多個節點上的 NoSQL 資料庫中。

此外，我們還需要負載平衡器來均勻分發傳入請求。我們還新增了應用程式伺服器作為客戶端的入口點，以便它們可以將請求轉發到適當的微服務。這些 Web 伺服器封裝了內部系統架構，並提供其他服務，例如身份驗證、監控、請求整形、管理等。


## API design (API 設計)
由於系統向使用者提供建議並將熱門查詢新增到資料庫中，因此我們需要以下 API。

### Get suggestion (獲取建議)
```
getSuggestions(prefix)
此 API 調用從伺服器檢索建議。此調用通過建議服務進行，並將響應返回給客戶端。

下表解釋了傳遞給 API 調用的參數：
Parameter (參數)       Description (描述)

prefix                 這指的是使用者在搜尋欄中輸入的任何內容。
```

### Add trending queries to the database (將熱門查詢新增至資料庫)
```
addToDatabase(query)
如果查詢已被搜尋並且超過了一定閾值，此 API 調用將通過組裝器將熱門查詢新增到資料庫中。
Parameter (參數)   Description (描述)

query              這表示超過預定義限制的頻繁搜尋查詢。
```

我們應該使用 AJAX 非同步更新查詢。AJAX 是一組 Web 開發技術。它允許網頁與伺服器交換少量資料 (如在預輸入建議系統中)，而不會干擾現有網頁的顯示和行為。
