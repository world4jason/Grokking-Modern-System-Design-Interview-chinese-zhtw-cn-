# System Design: Distributed Logging (系統設計：分佈式日誌記錄)
## Logging (日誌記錄)
日誌文件記錄軟體應用程式中發生的事件的詳細資訊。詳細資訊可能包括微服務、事務、服務操作或任何有助於調試系統中事件流的內容。日誌記錄對於監控應用程式的流程至關重要。

## Need for logging (日誌記錄的需求)
日誌記錄對於了解分佈式系統中事件的流程至關重要。這似乎是一項乏味的任務，但在面臨故障或安全漏洞時，日誌記錄有助於查明系統何時以及如何發生故障或受到損害。它還可以幫助找出故障或違規的根本原因。它減少了修復系統的平均時間。

為什麼我們不簡單地打印出我們的語句來了解應用程式的流程？這是可能的，但並不理想。簡單的打印語句無法跟踪消息的嚴重性。打印函數的輸出通常會轉到終端，而我們需要的可能是將此類資料持久保存到本地或遠程存儲中。 此外，我們可能有數百萬個打印語句，因此最好正確地構建和存儲它們。

在許多節點上運行的服務的並發活動可能需要因果關係資訊才能正確地將正確的事件流拼接在一起。在處理分佈式系統中的因果關係時，我們必須小心。我們使用日誌服務來適當管理我們分佈式軟體的診斷和探索性資料。

日誌記錄使我們能夠理解我們的代碼，定位不可預見的錯誤，修復識別出的錯誤，並可視化應用程式的性能。通過這種方式，我們意識到生產環境是如何運作的，並且我們知道進程是如何在系統中運行的。

日誌分析有助於我們處理以下場景：
- 排除應用程式、節點或網絡問題。
- 遵守內部安全政策、外部法規和合規性。
- 識別並應對資料洩露和其他安全問題。
- 為了推薦系統輸入而理解使用者的行為。
