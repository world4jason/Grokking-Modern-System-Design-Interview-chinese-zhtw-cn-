BigQuery

Apache Kafka

```
2 假設擁有數百萬追蹤者的公眾人物帳戶在 Twitter 上發布了一條推文。您的系統將需要處理該帳戶數百萬追蹤者與這條推文的數百萬次互動。假設系統知道推文的受眾詳細資訊，以下哪種解決方案是處理此流量的最佳方法？

A)
在中央資料中心為公眾人物專門提供幾台伺服器。

B)
增加或專門提供一些伺服器到大部分受眾所屬的特定位置。

C)
增加位於不同地區的所有 Twitter 資料中心的伺服器數量，以處理海量流量。

```

```
5 (選擇所有適用的選項。) 我們討論了客戶端負載平衡器的工作原理以及它提供的好處。以下哪些選項被認為是客戶端負載平衡器的可能缺點？

A)
它們充當單點故障。

B)
它們不適合小規模應用程式，因為沒有用於服務的專用伺服器。

C)
它們增加了網路跳躍。

D)
當伺服器新增/刪除或演算法修改時，它們使更新所有客戶端變得更加困難。
```

Answers (答案)

```
1
假設您在一家提供社交服務的知名公司擔任工程師。您的任務是改進實時事件處理以獲得頻繁的結果。在這種情況下，以下哪種工具對您幫助最大？

A)
BigQuery

Explanation (解釋)
BigQuery 是一個無伺服器、完全託管的資料倉庫，允許對海量資料進行可擴展分析。

Correct Answer (正確答案)
B)
Apache Kafka

Explanation (解釋)
Apache Kafka 是一個用於分散式實時事件處理和儲存的框架。

C)
Vertica

Explanation (解釋)
Vertica 是一個列式資料儲存，可以管理海量資料，並在通常耗時的情況下提供快如閃電的查詢效能。

D)
FlockDB

Explanation (解釋)
FlockDB 是一個分散式、容錯的圖資料庫，用於處理大型網路圖。
```


```
2
假設擁有數百萬追蹤者的公眾人物帳戶在 Twitter 上發布了一條推文。您的系統將需要處理該帳戶數百萬追蹤者與這條推文的數百萬次互動。假設系統知道推文的受眾詳細資訊，以下哪種解決方案是處理此流量的最佳方法？

A)
在中央資料中心為公眾人物專門提供幾台伺服器。

Explanation (解釋)
增加中央資料中心的負擔，同時也增加了延遲。

Correct Answer (正確答案)
B)
增加或專門提供一些伺服器到大部分受眾所屬的特定位置。

C)
增加位於不同地區的所有 Twitter 資料中心的伺服器數量，以處理海量流量。

Explanation (解釋)
如果大部分流量來自少數幾個地區，那麼增加其他資料中心的伺服器是無用的，也是資源浪費。

D)
按區域向追蹤者顯示推文，以避免處理海量流量。

Explanation (解釋)
所有與推文有連結的使用者都必須收到推文。所以，它沒有履行服務。
```


```
3
當使用者發送首頁時間線請求時，系統會向使用者響應指定數量的 Top-k 推文。系統根據什麼基礎識別特定使用者的 Top-k 推文？

A)
使用者按讚的推文 (由未關注帳戶發布) 和趨勢。

Explanation (解釋)
趨勢指標在這裡無關緊要。

B)
使用者的追蹤者和位置。

Explanation (解釋)
使用者不會收到他們的追蹤者發布的推文。

Correct Answer (正確答案)
C)
使用者關注帳戶的推文和關注帳戶轉發的推文。

D)
位置和未關注帳戶

Explanation (解釋)
只要推文沒有被推廣，使用者就不會收到未關注帳戶的推文。
```


```
4
分片計數器是一種有效的解決方案，可以單獨計算數千名名人推文上的多個互動 (按讚或查看)。問題是當使用者與任何推文互動時，它需要立即響應 (例如，按讚數的增加或減少)。以下哪種解決方案在這方面有所幫助？

A)
在伺服器快取中維護計數器。

Explanation (解釋)
在快取中管理數百萬個計數器很困難，因為它們的大小 (記憶體) 有限。

Correct Answer (正確答案)
B)
根據名人的歷史 (最近幾條推文的受眾)，將特定計數器的指定分片放置在最終使用者附近。

Explanation (解釋)
在這種情況下，最近的伺服器將立即響應按讚或查看推文的最終使用者。

C)
在中央資料中心增加屬於該推文的多個計數器的分片數量。

Explanation (解釋)
這將增加延遲，因為中央資料中心遠離最終使用者，並且也增加了中央伺服器的負擔。

D)
在客戶端快取中使用推文的指定詳細資訊創建實時計數器。

Explanation (解釋)
該解決方案有多個問題，例如客戶端快取有限。例如，如果最終使用者對許多推文執行許多操作 (按讚、查看、回覆)，則在快取中創建和管理許多計數器是困難的。其次，如果客戶端按讚了一條貼文，並且相關計數器在客戶端快取中遞增。但是由於某種原因，客戶端快取在將該詳細資訊移動到應用程式伺服器之前變空 (由於任何故障)。所以，這個解決方案是不可靠的。
```
