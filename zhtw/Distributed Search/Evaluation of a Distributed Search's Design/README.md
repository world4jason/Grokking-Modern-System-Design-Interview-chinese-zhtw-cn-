# Evaluation of a Distributed Search's Design (評估分佈式搜尋的設計)

## Availability (可用性)
我們先利用分佈式存儲來存儲這些項目：

- 索引器爬取的文檔。
- 索引節點生成的倒排索引。

資料在分佈式存儲中的多個區域進行複製，這使得索引和搜尋的跨區域部署更加容易。索引和搜尋節點組只需要在不同的可用區進行複製。因此，我們在不同的可用區部署索引和搜尋節點集群。因此，如果一個地方發生故障，我們可以處理來自另一個集群的請求。多組索引和搜尋節點有助於實現高索引和搜尋可用性。此外，在每個集群中，如果一個節點死亡，另一個節點可以取代它的位置。

索引是離線執行的，不在使用者的關鍵路徑上。我們不需要同步複製索引操作。沒有必要使用剛剛添加到索引的最新資料來響應使用者搜尋查詢。因此，我們不必等待新索引的複製來響應搜尋查詢。這使得搜尋對使用者可用。

```
注意：一旦我們在所有索引節點組中複製最新資料並且搜尋節點已經下載它，那麼搜尋查詢將在最新資料上執行。
```

## Scalability (可擴展性)
分區是搜尋系統擴展的重要組成部分。當我們增加分區數量並向索引和搜尋集群添加更多節點時，我們可以在資料索引和查詢方面進行擴展。

索引和搜尋過程的強隔離有助於索引和搜尋獨立動態地擴展。

## Fast search on big data (大數據上的快速搜尋)
我們利用了許多節點，每個節點都在較小的倒排索引上並行執行搜尋查詢。然後合併每個搜尋節點的結果並將其返回給使用者。

## Reduced cost (降低成本)
我們使用更便宜的機器來計算索引和執行搜尋。如果一個節點發生故障，我們不必重新計算完整的索引。相反，只需再次索引某些文檔。

## Conclusion (結論)
幾乎每個應用程式都需要搜尋系統。我們已經看到，開發一個可以在單個節點上運行的搜尋系統是不可能的。我們利用並行計算框架和低成本機器來構建一個可用、可擴展且高性能的搜尋系統。
