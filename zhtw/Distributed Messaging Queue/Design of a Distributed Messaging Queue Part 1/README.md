# Design of a Distributed Messaging Queue: Part 1 (分佈式消息隊列的設計：第 1 部分)
到目前為止，我們已經討論了分佈式消息隊列的需求和設計注意事項。現在，讓我們開始學習分佈式消息隊列的高級設計。

## Distributed messaging queue (分佈式消息隊列)
與單伺服器消息隊列不同，分佈式消息隊列駐留在多個伺服器上。分佈式消息隊列有其自身的挑戰。但是，如果設計得當，它可以解決單伺服器消息隊列的缺點。

接下來的章節通過去介紹更具容錯性的消息隊列架構，重點關注設計分佈式消息隊列的可擴展性、可用性和持久性問題。

### High-level design (高級設計)
在深入探討設計之前，讓我們假設以下幾點，以使討論更簡單易懂。在接下來的材料中，我們將討論以下假設如何使我們能夠消除消息隊列的單伺服器解決方案中的問題。

1. 隊列資料在集群內部使用主從或類似仲裁的系統進行複製 (請閱讀資料複製課程以了解更多詳細資訊)。如果隊列太長而無法容納在伺服器上，我們的服務可以使用資料分區。我們可以為此使用類似一致性哈希的方案，或者我們可以使用鍵值存儲，其中鍵可能是消息的序列號。在這種情況下，每個分片都被適當地複製 (有關此內容的更多詳細資訊，請參閱分區課程)。

2. 我們還假設我們的系統可以根據需要自動擴展和自動收縮資源，以優化利用資源。

我們設計的基本組件詳述如下。

#### Load balancer (負載平衡器)
負載平衡器層接收來自生產者和消費者的請求，這些請求被轉發到前端伺服器之一。這一層由許多負載平衡器組成。因此，請求以最小的延遲被接受並提供高可用性。

#### Front-end service (前端服務)
前端服務由分佈在資料中心的無狀態機器組成。前端提供以下服務：

- **Request validation (請求驗證)**：這確保請求的有效性，並檢查它是否包含所有必要的資訊。

- **Authentication and authorization (身份驗證和授權)**：此服務檢查請求者是否為有效使用者，以及這些服務是否授權給請求者使用。

- **Caching (快取)**：在前端快取中，存儲與常用隊列相關的元資料資訊。與此同時，使用者相關資料也緩存在此處，以減少對身份驗證和授權服務的請求時間。

- **Request dispatching (請求分發)**：前端還負責調用另外兩個服務：後端和元資料存儲。區分對這兩個服務的調用是前端的職責之一。

- **Request deduplication (請求去重)**：前端還跟蹤與所有請求相關的資訊，因此，它還防止將相同的請求放入隊列。決定如何處理重複項可能像在存儲中搜索哈希鍵一樣簡單。如果在存儲中找到某些內容，這意味著重複，並且可以拒絕該消息。

```
這裡可能會出現一個問題：如何識別兩個 (或更多) 請求是重複的。有幾種方法可以識別重複消息；然而，最可靠的方法是計算消息內容 (而不是消息屬性) 的哈希 (最好是 SHA256)。這樣，如果傳入的消息具有相同的內容，服務將根據它們的哈希檢測重複。
```

- **Usage data collection (使用資料收集)**：這是指收集可用於審計目的的實時資料。

#### Metadata service (元資料服務)
此組件負責在元資料存儲和快取中存儲、檢索和更新隊列的元資料。每當創建或刪除隊列時，元資料存儲和快取都會相應更新。元資料服務充當前端伺服器和資料層之間的中間件。由於隊列的元資料保存在快取中，因此前端伺服器首先檢查快取以獲取與收到請求相關的任何相關資訊。如果發生快取未命中，則從元資料存儲中檢索資訊並相應地更新快取。

```
store：負責存儲與系統中所有可用隊列相關的元資料的持久資料存儲集群。

cache：每當客戶端請求到達時經常訪問的元資料集群。
```

組織元資料快取集群有兩種不同的方法：

1. 如果需要存儲的元資料很小並且可以駐留在單台機器上，那麼它將在每個集群伺服器上複製。隨後，可以從任何隨機伺服器提供請求。在這種方法中，還可以在前端伺服器和元資料服務之間引入負載平衡器。

[在前端伺服器和元資料服務之間引入了負載平衡器](./lb.jpg)

2. 如果需要存儲的元資料太大，則可以遵循以下模式之一：

- 第一種策略是使用分片方法將資料劃分為不同的分片。可以根據某些分區鍵或哈希技術執行分片，正如在資料庫分區課程中所討論的那樣。每個分片存儲在集群中的不同主機上。此外，每個分片還在不同的主機上複製以增強可用性。在這種集群組織方法中，前端伺服器具有分片和主機之間的映射表。因此，前端伺服器負責將請求重定向到存儲資料的主機。

[映射表駐留在前端伺服器上](./mapping_table1.jpg)

- 第二種方法與第一種方法類似。但是，此方法中的映射表存儲在每個主機上，而不僅僅是存儲在前端伺服器上。因此，任何隨機主機都可以接收請求並將其轉發到資料駐留的主機。此技術適用於讀取密集型應用程式。

[映射表駐留在每個元資料伺服器上](./mapping_table2.jpg)

在我們關於分佈式消息隊列的討論中，我們重點關注了這種類型隊列的高級設計。此外，我們探索了高級設計中的每個組件，包括：

- Front-end servers and the services required of them for smooth operations. (前端伺服器及其平穩運行所需的服務。)
- Load balancers. (負載平衡器。)
- Metadata services. (元資料服務。)
- Metadata clusters and their organization. (元資料集群及其組織。)

設計的一個重要部分是後端伺服器的組織，用於隊列創建、刪除和其他此類操作。下一課重點關注後端伺服器的組織和隊列的管理，以及與消息傳遞和檢索相關的其他重要操作。
