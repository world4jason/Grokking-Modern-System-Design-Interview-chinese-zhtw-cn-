# Design of a Distributed Messaging Queue: Part 2 (分佈式消息隊列的設計：第 2 部分)
在上一課中，我們討論了前端伺服器和元資料服務的職責。在本課中，我們將重點關注隊列和消息存儲設計的主要部分：後端服務。

## Back-end service (後端服務)
這是發生主要活動的架構的核心部分。當前端收到消息時，它會參考元資料服務來確定需要發送消息的主機。然後將消息轉發到該主機，並在相關主機上進行複製，以克服可能的可用性問題。使用以下兩種模型之一可以在不同主機的集群中執行消息複製：

1. **Primary-secondary model (主從模型)**
2. **A cluster of independent hosts (獨立主機集群)**

在深入探討這些模型的細節之前，讓我們討論負責隊列管理的兩種類型的集群管理器：內部和外部集群管理器。這兩個集群管理器之間的區別如下表所示。

```

外部集群管理器                                                                    它管理集群內隊列的分配。

它管理跨集群的隊列分配。                                                          它了解集群內的每個節點。

                                                                                 它了解每個集群。但是，它沒有關於集群內存在的每個主機的資訊。

```

### Primary-secondary model (主從模型)
在主從模型中，每個節點都被視為一組隊列的主主機。主主機的職責是接收對特定隊列的請求，並完全負責資料複製。前端接收請求，前端又與元資料服務通訊以確定請求的主主機。

例如，假設我們有兩個 ID 為 101 和 102 的隊列駐留在四個不同的主機 A、B、C 和 D 上。在此示例中，實例 B 是隊列 101 的主主機，而複製隊列 101 的輔助主機是 A 和 C。當前端接收消息請求時，它通過元資料服務從內部集群管理器識別主伺服器。消息從主實例中檢索，主實例還負責在使用後刪除原始消息及其所有副本。

如下圖所示，內部集群管理器是一個負責在主主機、輔助主機和隊列之間進行映射的組件。此外，它還有助於選擇主主機。因此，它需要可靠、可擴展且高效。

### A cluster of independent hosts (獨立主機集群)

在涉及獨立主機集群的方法中，我們有多個分佈在資料中心的多個獨立主機集群。當前端收到消息時，它通過外部集群管理器的元資料服務確定相應的集群。然後將消息轉發到集群中的隨機主機，該主機將消息複製到存儲隊列的其他主機中。

```
Question
問題
集群內的隨機主機如何在同一集群內其他主機上的隊列中複製資料 (即消息)？

Answer
答案
每個主機都包含集群內隊列和主機之間的映射，從而使複製更容易。

假設我們有一個集群，比如 Y，有主機 A、B 和 C。此集群有兩個 ID 為 101 和 103 的隊列存儲在不同的主機上，如下表所示。此表存儲在集群 Y 內的每個主機上。當隨機主機接收到 ID 為 103 的隊列的消息 (例如主機 C) 時，主機 C 會將此消息複製到存儲隊列 103 的其他主機上，即節點 A 和節點 B。
```

同樣的過程適用於接收來自消費者的消息請求。與第一種方法類似，隨機選擇的主機負責消息傳遞和成功處理消息後的清理。

此外，還引入了另一個名為外部集群管理器的組件，該組件負責維護隊列和集群之間的映射，如下圖所示。外部集群管理器還負責隊列管理和分配特定隊列的集群。

下圖說明了獨立主機集群。有兩個集群 A 和 B，它們由多個節點組成。外部集群管理器具有隊列與其對應集群之間的映射表。每當前端收到對隊列的請求時，它就會確定隊列的相應集群，並將請求轉發到隊列所在的集群。該集群內的節點負責相應地存儲和發送消息。

[由分佈式隊列組成的獨立主機集群](./cluster.jpg)

```
Question
問題
在其他主機上複製消息時可能會出現什麼樣的異常？

Answer
答案
有兩種方法可以在駐留在多個主機上的隊列中複製消息。

1. Synchrounous replication (同步複製)
2. Asynchrounous replication (異步複製)

在同步複製中，主主機負責將消息複製到其他主機上的所有相關隊列中。在收到輔助主機的確認後，主主機然後通知客戶端有關消息接收的資訊。在這種方法中，消息在所有隊列副本中保持一致；但是，這會花費額外的通訊延遲，並且在進行選舉以將輔助主機提升為主主機時導致部分不可用或完全不可用。

在異步複製中，一旦主主機收到消息，它就會確認客戶端，在下一步中，它開始在其他主機中複製消息。這種方法伴隨著其他問題，例如複製延遲和一致性問題。

根據應用程式的需求，我們可以選擇其中之一。
```
