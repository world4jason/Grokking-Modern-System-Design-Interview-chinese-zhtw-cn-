# System Design: The Distributed Messaging Queue (系統設計：分佈式消息隊列)
## What is a messaging queue? (什麼是消息隊列？)
消息隊列是稱為生產者和消費者的交互實體之間的中間組件。生產者生成消息並將其放入隊列中，而消費者從隊列中檢索消息並處理它們。可能有多個生產者和消費者同時與隊列交互。

### Motivation (動機)
消息隊列具有多種優勢和用例。

- **Improved performance (提高性能)**：消息隊列支持兩個交互實體 (生產者和消費者) 之間的異步通訊，並消除它們的相對速度差異。生產者將消息放入隊列而無需等待消費者。同樣，消費者在消息可用時處理消息。此外，隊列通常用於將較慢的操作從關鍵路徑中分離出來，從而有助於減少客戶端感知的延遲。例如，生產者進程不是等待特定任務完成很長時間，而是發送一條消息 (如果有多個請求，該消息將保留在隊列中) 以執行所需的任務並繼續其操作。消費者可以使用另一個隊列通知我們處理的命運，無論是成功還是失敗。

- **Better reliability (更好的可靠性)**：通過消息隊列分離交互實體使系統更具容錯能力。例如，生產者或消費者可以獨立發生故障而不會影響其他實體，並在以後重新啟動。此外，在多個伺服器上複製消息隊列可確保系統在一個或多個伺服器宕機時的可用性。

- **Granular scalability (精細的可擴展性)**：異步通訊使系統更具可擴展性。例如，許多進程可以通過消息隊列進行通訊。此外，當請求數量增加時，我們會將工作負載分配給多個消費者。因此，應用程式可以完全控制根據其當前需求調整生產者或消費者進程的數量。

- **Easy decoupling (輕鬆解耦)**：消息隊列解耦了系統中不同實體之間的依賴關係。交互實體通過消息進行通訊，並且彼此不知道對方的內部工作機制。

- **Rate limiting (速率限制)**：消息隊列還有助於吸收任何負載峰值並防止服務過載，當需要避免丟棄任何傳入請求時，充當速率限制的基本形式。

- **Priority queue (優先級隊列)**：可以使用多個隊列來實現不同的優先級——例如，每個優先級一個隊列——並為更高優先級的隊列提供更多的服務時間。

### Messaging queue use cases (消息隊列用例)
消息隊列在單伺服器和分佈式環境中都有許多用例。例如，它可用於一個操作系統內的進程間通訊。它還支持分佈式環境中進程之間的通訊。下面討論了消息隊列的一些用例。

1. **Sending many emails (發送許多電子郵件)**：電子郵件用於多種目的，例如共享資訊、帳戶驗證、重置密碼、營銷活動等。為不同目的編寫的所有這些電子郵件不需要立即處理，因此它們不會干擾系統的核心功能。在這種情況下，消息隊列有助於協調不同發送者和接收者之間的大量電子郵件。

```
核心功能包括編寫、格式化、在電子郵件中添加相關對象以及發送和接收電子郵件。
```

2. **Data post-processing (資料後處理)**：許多多媒體應用程式需要處理內容以滿足不同的觀看者需求，例如在移動電話和智能電視上消費。通常，應用程式將內容上傳到存儲中，並使用消息隊列離線後處理內容。這樣做大大減少了客戶端感知的延遲，並使服務能夠在某個適當的時間安排離線工作——可能在計算能力不太繁忙的深夜。

3. **Recommender systems (推薦系統)**：一些平台使用推薦系統向使用者提供首選內容或資訊。推薦系統獲取使用者的歷史資料，對其進行處理，並預測相關內容或資訊。由於這是一項耗時的任務，因此可以在推薦系統和請求進程之間合併消息隊列，以增加並加快性能。
