# Introduction to a CDN (CDN 簡介)
## Proposed solution (提出的解決方案)
上一課中討論的所有問題的解決方案是內容傳遞網路 (CDN)。CDN 是一組地理上分散的代理伺服器。代理伺服器是客戶端和源伺服器之間的中間伺服器。代理伺服器放置在網路邊緣。由於網路邊緣靠近終端使用者，因此代理伺服器的放置有助於減少延遲並節省頻寬，從而快速將內容傳遞給終端使用者。除了作為簡單的代理伺服器之外，CDN 還增加了智慧功能。

網路邊緣是設備或本地網路與網際網路互動的區域。
```

我們可以通過在使用者附近放置一個小型資料中心並將資料副本儲存在那裡，將資料帶到離使用者更近的地方。CDN 主要儲存兩種類型的資料：靜態和動態。CDN 主要通過使資料更接近其使用者來解決傳播延遲問題。CDN 提供者盡最大努力通過路徑提供足夠的頻寬，並使資料更接近使用者 (可能在他們的 ISP 內)。 他們還試圖減少傳輸和排隊延遲，因為 ISP 可能在自治系統內具有更多可用頻寬。

static data (靜態資料)：這種類型的資料不經常更改，並在伺服器上保留很長一段時間。
dynamic data (動態資料)：這種類型的資料更改最頻繁——例如，時事通訊、廣告、即時影片等。
```

讓我們看看 CDN 解決所討論問題的不同方式：
- **High latency (高延遲)**：CDN 將內容帶到離終端使用者更近的地方。因此，它減少了物理距離和延遲。
- **Data-intensive applications (資料密集型應用程式)**：由於資料的路徑僅包括 ISP 和附近的 CDN 組件，因此通過特定區域內的少數 CDN 組件為大量使用者提供服務沒有問題。如下所示，源資料中心只需向本地 CDN 組件提供一次資料，而本地 CDN 組件可以單獨向不同使用者提供資料。沒有使用者必須從源伺服器下載自己的資料副本。

注意：CDN 提供者使用各種串流協定來傳遞動態內容。例如，CDNsun 使用即時訊息協定 (RTMP)、HTTP Live Streaming (HLS)、即時串流協定 (RTSP) 等來傳遞動態內容。
```

- **Scarcity of data center resources (資料中心資源的稀缺性)**：CDN 用於服務熱門內容。由於這個原因，大多數流量在 CDN 處處理，而不是在源伺服器處處理。因此，不同的本地或分散式 CDN 組件分擔了源伺服器上的負載。

注意：一些知名的 CDN 提供者包括 Akamai、StackPath、Cloudflare、Rackspace、Amazon CloudFront 和 Google Cloud CDN。
```

問 (Question)
CDN 是否快取源伺服器中的所有內容？

答 (Answer)
不太可能。CDN 根據其功能快取相當一部分內容，並且主要快取靜態內容。
static content (靜態內容)：不經常更改的內容稱為靜態內容。
這也取決於內容的大小。例如，Netflix 可能將超過 90% 的電影儲存在 CDN 中，而對於像 YouTube 這樣的服務，由於內容的巨大體積，這可能不可行。

## Requirements (需求)
讓我們看看我們期望從 CDN 獲得的功能和非功能需求。

### Functional requirements (功能性需求)
- **Retrieve (檢索)**：根據 CDN 模型的類型——推送或拉取，CDN 應該能夠從源伺服器檢索內容。我們將在接下來的課程中介紹 CDN 模型。
- **Request (請求)**：代理伺服器的內容傳遞是在使用者的請求下進行的。CDN 代理伺服器應該能夠在這方面回應每個使用者的請求。
- **Deliver (傳遞)**：在推送模型的情況下，源伺服器應該能夠將內容發送到 CDN 代理伺服器。
- **Search (搜尋)**：CDN 應該能夠針對使用者查詢在 CDN 基礎設施內對快取或其他儲存的內容執行搜尋。
- **Update (更新)**：在大多數情況下，內容來自源伺服器，但如果我們在 CDN 中運行腳本，CDN 應該能夠在 PoP 中的對等 CDN 代理伺服器內更新內容。
- **Delete (刪除)**：根據內容的類型 (靜態或動態)，應該可以在一段時間後從 CDN 伺服器中刪除快取的條目。

[CDN 的功能需求](./req.jpg)

存取點 (Point of Presence - PoP) 是一個物理位置，允許兩個或多個網路或設備相互通訊。通常，每個 CDN PoP 都有大量的快取伺服器。
```

### Non-functional requirements (非功能性需求)
- **Performance (效能)**：最小化延遲是 CDN 的核心任務之一。提出的設計應具有儘可能小的延遲。
- **Availability (可用性)**：由於其有效性，預計 CDN 隨時可用。可用性包括防止 DDoS 等攻擊的保護。
- **Scalability (可擴展性)**：越來越多的使用者將從 CDN 請求內容。我們提出的 CDN 設計應該能夠隨著需求的增加而水平擴展。
- **Reliability and security (可靠性和安全性)**：我們的 CDN 設計應確保沒有單點故障。除了故障之外，設計的 CDN 必須可靠地處理大量流量負載。此外，CDN 應為託管內容提供針對各種攻擊的保護。

在 DDoS 攻擊中，惡意代理通過發送大量請求來淹沒源伺服器或應用程式伺服器。
```

## Building blocks we will use (我們將使用的構建塊)
CDN 的設計利用了以下構建塊：

[CDN 設計中使用的構建塊](./bb.jpg)

- **DNS** 是將人類友好的 CDN 網域名稱映射到機器可讀 IP 地址的服務。此 IP 地址將把使用者帶到指定的代理伺服器。
- **Load balancers (負載平衡器)** 在運行的代理伺服器之間分發數百萬個請求。
