# Evaluation of CDN's Design (CDN 設計的評估)

## Evaluation (評估)
在這裡，我們看看我們的設計如何滿足我們在上一課中討論的需求。我們的主要需求是高效能、可用性、可擴展性、可靠性和安全性。讓我們逐一討論。

### Performance (效能)
CDN 通過最小化延遲來實現高效能。一些最小化延遲的關鍵設計決策如下：
- 代理伺服器通常從 RAM 提供內容。
- CDN 代理伺服器位於使用者附近，以提供對內容的更快存取。
- CDN 也可以是位於 ISP 或網際網路交換點 (IXP) 的代理伺服器提供者，以處理高流量。
- 請求路由系統確保將使用者引導至最近的代理伺服器。我們將在下一課詳細討論請求路由系統。
- 代理伺服器將長尾內容 (long-tail content) 儲存在 SSD 或 HDD 等非揮發性儲存系統中。從這些資源提供服務比我們從源伺服器提供內容看到的延遲更小。

- 正如之前所討論的，代理伺服器可以分層實作，如果一層沒有內容，則可以由下一層代理伺服器處理請求。例如，邊緣代理伺服器可以請求父代理伺服器。當大多數流量來自這些 ISP 區域時，將代理伺服器放置在特定的 ISP 可能是最佳選擇。

### Availability (可用性)
由於其分散式特性，CDN 可以處理大量流量。CDN 通過其快取內容確保可用性，這些內容在源伺服器發生故障時充當備份。此外，如果 CDN 中的一個或多個代理伺服器停止工作，其他運行中的代理伺服器將介入並繼續驅動 Web 流量。此外，可以通過冗餘使邊緣代理伺服器可用，方法是將資料複製到盡可能多的代理伺服器，以避免單點故障並滿足請求負載。最後，我們可以使用負載平衡器將使用者的請求分發到附近活動的代理伺服器。

### Scalability (可擴展性)
CDN 的設計通過以下方式促進可擴展性：

- 它將內容帶到離使用者更近的地方，並消除了高頻寬的需求，從而確保可擴展性。
- 通過以邊緣代理伺服器的形式增加讀取副本的數量，可以實現水平可擴展性。
- 可以使用我們上面描述的代理伺服器的分層架構來處理單個代理伺服器的水平可擴展性和儲存容量的限制。

### Reliability and security (可靠性和安全性)
CDN 通過仔細實作維護週期並在需要時整合額外的硬體和軟體來確保沒有單點故障。除了故障之外，CDN 通過將負載平均分發到邊緣代理伺服器來處理大量流量負載。我們可以使用清洗伺服器 (scrubber servers) 來防止 DDoS 攻擊並安全地託管內容。此外，我們可以使用心跳協定來監控伺服器的健康狀況並剔除故障伺服器。即時應用程式還構建自己指定的 CDN，以防止內容洩露問題並安全地向其終端使用者提供內容。

## Conclusion (結論)
自 1990 年代問世以來，CDN 在提供高可用性和低延遲內容傳遞方面發揮了至關重要的作用。如今，CDN 被認為是提高巨型服務整體效能的關鍵參與者。
