# Maintainability (可維護性)

## What is maintainability? (什麼是可維護性？)
除了構建系統之外，隨後的主要任務之一是通過查找和修復錯誤、添加新功能、保持系統平台更新以及確保系統平穩運行來保持系統正常運行。定義示例系統設計的此類需求的一個顯著特徵是可維護性。我們可以進一步將可維護性的概念分為三個潛在方面：

可操作性：這是我們可以輕鬆確保系統在正常情況下平穩運行並在故障下恢復正常條件的容易程度。

清晰度：這是指代碼的簡單性。代碼庫越簡單，就越容易理解和維護，反之亦然。

可修改性：這是系統無需任何麻煩即可集成修改後的、新的和不可預見的功能的能力。

### Measuring maintainability (測量可維護性)
可維護性 M 是指服務在故障發生後的指定時間內恢復其功能的概率。M 衡量服務恢復其正常運行條件的方便程度和速度。

例如，假設組件在半小時內的定義可維護性值為 95%。在這種情況下，在半小時內將組件恢復到完全活動形式的概率為 0.95。

```
注意：可維護性讓我們深入了解系統在運行時進行維修和修改的能力。
```
我們使用 MTTR (平均修復時間) 作為衡量 M 的指標。

MTTR = 總維護時間 / 總維修次數

換句話說，MTTR 是修復和恢復故障組件所需的平均時間。我們的目標是使 MTTR 的值盡可能低。

### Maintainability and reliability (可維護性和可靠性)

可維護性可以與可靠性密切相關地更清楚地定義。它們之間的唯一區別是感興趣的變量。可維護性是指修復時間，而可靠性是指修復時間和故障時間。結合可維護性和可靠性分析可以幫助我們獲得可用性、停機時間和正常運行時間的見解。
