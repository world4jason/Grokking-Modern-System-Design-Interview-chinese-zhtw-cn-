# Fault Tolerance (容錯)

## What is fault tolerance? (什麼是容錯？)
現實世界的大規模應用程式運行數百台伺服器和資料庫，以適應數十億使用者的請求並存儲重要資料。這些應用程式需要一種機制，通過避免單點故障來幫助保護資料安全並避免重新計算計算密集型任務。

容錯是指即使一個或多個組件發生故障，系統仍能持續執行的能力。在這裡，組件可以是軟件或硬件。構想一個百分之百容錯的系統實際上是非常困難的。

讓我們討論一些容錯成為必要的重要特徵。

可用性側重於通過 24/7 可訪問來接收每個客戶端的請求。

可靠性涉及通過對每個客戶端的請求採取指定操作來進行響應。

### Fault tolerance techniques (容錯技術)
故障發生在硬件或軟件級別，最終會影響資料。考慮到系統結構，可以通過多種方法實現容錯。讓我們討論對大多數設計都重要且合適的技術。

#### Replication (複製)
最廣泛使用的技術之一是基於複製的容錯。使用此技術，我們可以複製服務和資料。我們可以將故障節點替換為健康節點，將故障資料存儲替換為其副本。大型服務可以透明地進行切換，而不會影響最終客戶。

我們在單獨的存儲中創建資料的多個副本。當資料發生任何更新時，所有副本都需要定期更新以保持一致性。更新副本中的資料是一項具有挑戰性的工作。當系統需要強一致性時，我們可以同步更新副本中的資料。但是，這會降低系統的可用性。當我們可以容忍最終一致性時，我們也可以異步更新副本中的資料，從而導致在所有副本收斂之前讀取陳舊資料。因此，兩種一致性方法之間存在權衡。我們在故障下的可用性或一致性上做出妥協——CAP 定理概述的一個現實。

#### Checkpointing (檢查點)
檢查點是一種在系統狀態一致時將系統狀態保存在穩定存儲中的技術。檢查點在不同時間間隔的許多階段執行。主要目的是保存給定點的計算狀態。當系統發生故障時，我們可以從上一個檢查點獲取最後計算的資料，並從那裡開始工作。

檢查點也與我們在複製中遇到的問題相同。當系統必須執行檢查點時，它確保系統處於一致狀態，這意味著所有進程都已停止。這種類型的檢查點稱為同步檢查點。另一方面，在不一致狀態下的檢查點會導致資料不一致問題。讓我們看下面的插圖來了解一致狀態和不一致狀態之間的區別：
